# Задача для `mango-ba-ai-runtime`: пилот в Qwen Chat

**Назначение.** Этот текст — готовый мандат для issue в [`G-Ivan-A/mango-ba-ai-runtime`](https://github.com/G-Ivan-A/mango-ba-ai-runtime). Он готовит отдельный сценарий быстрой проверки BCREQ через [`chat.qwen.ai`](https://chat.qwen.ai/) с публичными или синтетическими входами. Его можно приложить к issue или передать агенту в **том** репозитории. Само размещение этого файла не меняет внешний репозиторий и не делает существующий GigaCode runtime пакетом для чата.

**Граница доказанного.** Официальная документация [GigaCode CLI](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/commands) описывает локальный shell. Для веб-сервиса `chat.qwen.ai` такого контракта на исполнение файлов данного GitHub-репозитория и автоматический вызов Python-гейта в доступных первичных источниках не найдено. Наличие ссылки в сообщении **не доказывает**, что чат прочитал все файлы, нужную ревизию или выполнил код. Поэтому результат чата — кандидат; формальное принятие выполняется локально или в CI отдельной командой. [Qwen Code CLI](https://github.com/QwenLM/qwen-code) и Qwen Chat — разные продукты; инструкции клиента CLI сюда не переносить.

## Готовый текст issue для внешнего репозитория

> **Title:** `pilot: добавить изолированный quick-check BCREQ через Qwen Chat`
>
> **User story:** Я как БА хочу открыть проверенный публичный снимок модели, дать Qwen Chat синтетический запрос и получить BCREQ-кандидат с явным перечнем источников и пробелов, чтобы быстро проверить логику до запуска полноценного агентного пакета. Я должен видеть, что чат реально прочитал, а что осталось недоступным.
>
> **Source и границы:** Source модели — [`projects/ba-ai-process/`](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/tree/main/projects/ba-ai-process), архитектура Source → Distribution → Runtime — [ADR-017](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/projects/ba-ai-process/decisions/2026-09-adr-017-ba-ai-process-source-distribution.md). Целевой репозиторий — [`mango-ba-ai-runtime`](https://github.com/G-Ivan-A/mango-ba-ai-runtime), сейчас он содержит более ранний GigaCode-срез (`.agents/skills/`, `routes/`, `contracts/`, `tools/`, `runs/.gitkeep`). Не удалять и не перезаписывать эти артефакты ради нового сценария. Работать через PR к этому репозиторию. `mango_ba_prompts` из [обсуждения команды Q](https://github.com/user-attachments/files/32652327/-.Q.250926.txt) — источник возможной публичной KB, но не названный issue #615 целевой runtime.
>
> **Работа:**
>
> 1. Перед правкой прочитать локальный `AGENTS.md`, issue/PR feedback и README runtime. Сверить дерево с исходным пакетом и pin Source revision SHA. Составить в PR таблицу: путь в Source, путь в runtime, скопировано/преобразовано/исключено и зачем. Не импортировать RRP, ADR, backlog, секреты или бизнес-прогоны в runtime. Текущие `.agents/skills/` сохранить как legacy GigaCode-срез до отдельного решения о его судьбе; в инструкции Qwen не выдавать их за нативные chat skills.
> 2. Добавить `docs/guides/07-qwen-chat-quick-check.md` и ссылку на него из `docs/guides/README.md` и корневого README. Guide должен быть самостоятельным для junior БА: предпосылки — браузер и доступ к Qwen Chat и публичному GitHub; для сохранения/машинной проверки — Git и Python 3 на разрешённом АРМ или CI. Указать, что локальная GPU не нужна для веб-чата. Для разработчика отдельно назвать версии Python/зависимостей, подтверждённые тестом пакета; не угадывать версии.
> 3. Сохранить существующие имена `AGENTS.md`, `docs/kb/`, `taxonomy/`, `contracts/`, `routes/`, `templates/`, `evaluation/`, `golden/`, `tools/`, `runs/`; добавить предусмотренный [ADR-017](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/projects/ba-ai-process/decisions/2026-09-adr-017-ba-ai-process-source-distribution.md) `meta-model/` в новом пакете, а новый верхнеуровневый каталог создавать только по локальной декларации структуры. Подготовить минимальный публичный комплект BCREQ с pin версии/хешей в `compilation-manifest.yaml` или новом versioned manifest после согласования миграции. В `meta-model/` — разрешённая копия активных контрактов, в `docs/kb/` — только санитизированные публичные материалы и их источник/версия. KB теперь находится в [`mango-ba-ai-runtime/docs/kb`](https://github.com/G-Ivan-A/mango-ba-ai-runtime/tree/main/docs/kb); её материалы автоматически не передавать во внешний чат: доступность каталога не доказывает право передачи каждого фрагмента.
> 4. Guide должен давать **два** способа подачи контекста. Сначала ссылка на immutable GitHub permalink (`/blob/<SHA>/...`), запрос в чате перечислить прочитанные пути, SHA и привести короткий проверяемый фрагмент из каждого. Если чат не может показать это, БА вручную вставляет или прикрепляет *только разрешённые публичные* выдержки `AGENTS.md`, нужного route, контракта, taxonomy и одного synthetic case, отмечая каждый путь и SHA. Нельзя объявлять весь репозиторий прочитанным по одной ссылке.
> 5. Пример prompt ниже должен вести по одному узлу/контракту, маркировать непроверенные утверждения и выводить `C-RK`-совместимый черновик следа либо явный список отсутствующих полей. Запретить фиктивные `PASS`, `G-mach`, «Python выполнен», «Confluence/Jira прочитан» и вымышленные цитаты. Qwen Chat не подключать к Mango AI API, корпоративным MCP или приватной KB.
> 6. Реальные файлы `runs/` не коммитить: в публичном Git остаётся `runs/.gitkeep`, а `runs/**` исключены `.gitignore` с исключением `.gitkeep`. Кандидаты и история чата сохраняются локально или в отдельном закрытом месте по политике компании. В публичный PR допускаются только синтетический вход, санитизированный вывод и ссылки на commit SHA.
> 7. Формальная приёмка кандидата происходит вне чата. CI репозитория запускает установленный из versioned Distribution `G-mach` и негативный тест. Для Working/Release после импорта актуального `bcreq_pipeline.py`: `python3 tools/bcreq_pipeline.py validate-working <Working.json>`; затем `compile` и `validate-release` согласно README конкретного пакета. Без этих файлов и успешного exit code результат помечается `unverified`; текстовое «прошёл» от модели не засчитывается. `G-human` отдельно проверяет смысл, продукт и источники.
>
> **Definition of Done:** PR внешнего репозитория даёт младшему БА рабочий public/synthetic walkthrough с указанием точного SHA и прочитанных файлов; fallback при недоступности GitHub-ссылки проверен; ложные заявления о Python/MCP отсутствуют; CI отвергает намеренно повреждённый Working и принимает валидный synthetic case; `runs/` и секреты не опубликованы; существующий GigaCode-срез остаётся доступным; README указывает, что Qwen Chat — временный quick check, а машинная проверка вынесена за пределы чата.
>
> **Review focus / открытое решение:** `mango-ba-ai-runtime` уже обслуживает GigaCode-срез, тогда как [ADR-017](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/projects/ba-ai-process/decisions/2026-09-adr-017-ba-ai-process-source-distribution.md) требует автономный runtime для одного Distribution. Рекомендация: этот PR делать аддитивным пилотом без удаления legacy, затем владелец решает, выделять ли `mango-ba-ai-runtime-qwen-chat` и переводить туда пилот. До решения обе среды не смешивать в одном quick-start.

## Минимальный prompt для проверочного чата

После выбора одного synthetic case и подтверждения файлов вставить:

```text
Ты проверяешь только публичный синтетический кейс BCREQ. Источник модели —
репозиторий G-Ivan-A/mango-ba-ai-runtime, commit <SHA>. Сначала перечисли
точные пути и SHA файлов, содержание которых действительно доступно тебе,
и приведи по одному короткому фрагменту для проверки. Если URL или файл
недоступен, скажи «не прочитан»; я вставлю разрешённый текст вручную.
Не утверждай, что выполнял Python, JSON Schema, G-mach, Jira, Confluence
или корпоративную KB. Выполни только шаг <node> из routes/rg-bcreq-v1.yaml
на синтетическом входе <case>. Дай черновик по указанному контракту,
реестр использованных фактов с точным путём/цитатой и список пробелов.
Каждый непроверенный факт пометь гипотезой. Машинную и человеческую приёмку
сделаем отдельно.
```

БА сверяет названные файлы с GitHub на том же SHA. Если чат не прочитал хотя бы один обязательный контракт шага, продолжать с маркировкой `unverified` или вставить разрешённую выдержку. Для настоящих заявок и корпоративных данных использовать только утверждённые среды 1/2. Эта инструкция не обещает, что Qwen Chat сможет открыть ссылку, выполнить код или сохранить состояние между беседами.
