# 4. Работа с агентом: реальная задача BCREQ

**Цель:** довести реальную задачу — ссылку на Jira или описание своими
словами — до проверенного Release. Вся работа идёт в
[окне OpenCode](01-junior-pilot.md#term-opencode-window): диалог с агентом и
две [команды пакета](01-junior-pilot.md#term-package-command) —
`/bcreq-start` в начале и `/bcreq-gate` для проверки. Терминал (вкладка 2)
нужен только чтобы убрать неудачный черновик и проверить всё перед
отправкой в Git.

Перед началом должны быть выполнены [установка](02-install.md) и
[развёртывание](03-deploy-package.md). [Учебный прогон](04-smoke-test.md) не
обязателен.

## Как устроена работа

| Шаг | Кто | Где | Что происходит |
|-----|-----|-----|----------------|
| 1 | Вы | — | Выбираете номер прогона [TASK ID](01-junior-pilot.md#term-task-id) |
| 2 | Вы → агент | Окно OpenCode, агент **Plan** | Команда `/bcreq-start TASK-ID входные данные` |
| 3 | Агент ⇄ вы | Окно OpenCode, агент **Plan** | Агент ищет подтверждения, перепроверяет, показывает нумерованные пункты; вы подтверждаете или отклоняете |
| 4 | Вы → агент | Окно OpenCode, агент **Build** | Вы пишете «пиши черновик» |
| 5 | Агент → вы | Окно OpenCode, [запрос разрешения](01-junior-pilot.md#term-permission) | Агент записывает `submissions\TASK-ID.json`; вы разрешаете запись **Allow once** |
| 6 | Вы | Окно OpenCode | Команда `/bcreq-gate TASK-ID` → `PASS` или `FAIL` |
| 7 | Вы (+ агент) | Окно OpenCode, агент **Plan** | Ваша проверка по чек-листу и решение |

При `FAIL` — шаги 4–6 повторяются с **новым** TASK ID
([почему](05-commands-reference.md#контроль-прогонов-один-task-id--один-прогон)).

## Шаг 1. Выберите TASK ID

- TASK ID — номер **прогона**, а не задачи в Jira: `TASK-` и минимум 4 цифры.
  Первая реальная задача — `TASK-0002` (номер `TASK-0001` занят учебным
  примером), дальше — следующие свободные номера.
- Свободный номер — тот, которого нет ни в папке `runs\`, ни в папке
  `submissions\`. Посмотреть во вкладке 2 терминала:

  ```powershell
  Get-ChildItem runs, submissions
  ```

- Ключ Jira (`BCREQ-123`) в качестве TASK ID не подходит: runner примет только
  `TASK-NNNN`. Ключ и ссылка на Jira записываются внутрь черновика как
  источник. Для себя ведите соответствие «TASK ID → задача Jira»
  (например, в заметках): одной задаче Jira может соответствовать несколько
  TASK ID — по одному на каждую попытку.

## Шаг 2. Начните задачу командой /bcreq-start

1. В окне OpenCode начните новую сессию командой `/new`. Одна задача Jira —
   одна сессия OpenCode.
2. **Введите команду пакета**, заменив номер и входные данные:

   ```text
   /bcreq-start TASK-0002 https://…/browse/BCREQ-123 клиент хочет выгружать журнал звонков
   ```

   Первое слово после команды — номер прогона, дальше — входные данные:
   ссылка на задачу в Jira или страницу Confluence и (или) суть задачи
   своими словами. Можно вставить и многострочный текст задачи.
3. Нажмите Enter.

- **Что делает:** OpenCode отправляет агенту **Plan** готовую стартовую
  фразу из `.opencode\commands\bcreq-start.md`: задача реальная, веди по
  шагам и согласовывай каждый пункт, ищи подтверждения сначала в
  корпоративной базе (`kb-readonly`), затем в `docs\kb\` по правилам
  `docs\kb-policy.md`, ничего не выдумывай, файлы не меняй до фразы
  «пиши черновик».
- **Ожидаемый результат:** OpenCode отвечает нумерованным списком. В пилоте
  доступен один процесс — «Сформировать бизнес-спецификацию по задаче
  BCREQ»; ответьте `1`.
- **Проверьте:** под полем ввода указан агент **Plan**; OpenCode не начал
  писать файлы.

Если OpenCode ответит, что номер не похож на `TASK-NNNN`, — повторите
команду с правильным номером. Если он ответит, что работает только с
учебным примером, — напишите «Задача реальная, см. AGENTS.md, пункт 1»; если
отказ повторится, передайте ответственному текст ответа.

### Какие входные данные можно дать

| Что у вас есть | Что написать после номера | Что сделает OpenCode |
|----------------|---------------------------|----------------------|
| Ссылка на задачу Jira, и администратор подключил корпоративную базу ([MCP](01-junior-pilot.md#term-mcp) `kb-readonly`) | `https://…/browse/BCREQ-123` | Попросит разрешения обратиться к `kb-readonly` (разрешите **Allow once**), прочитает задачу |
| Ссылка на Jira, но подключения нет | Ссылку **и** текст задачи, скопированный из Jira | Возьмёт суть из текста; ссылку запишет как адрес источника. Сам открыть Jira он не может |
| Страница Confluence | Так же, как Jira | Так же, как Jira |
| Только описание своими словами | `клиент хочет …` | Будет искать подтверждения в KB `docs\kb\`; чего не найдёт — станет открытым вопросом |

Проверить, есть ли подключение: команда `/mcps` в окне OpenCode — в списке
есть `kb-readonly` с отметкой о подключении. Если списка нет — подключения
нет ([как подключить](03-deploy-package.md#подключение-к-jira-и-confluence-необязательно)).

## Шаг 3. Согласуйте пункты с агентом

Агент показывает найденное нумерованными пунктами. Отвечайте по номерам:

```text
1 — да.
2 — нет: это относится к другому продукту, исключи.
3 — уточни: покажи дословную цитату и где она в документе.
```

Что агент должен согласовать с вами (все пункты нужны runner):

1. Суть задачи и цель клиента.
2. Что входит в изменение и что **не** входит (граница системы).
3. Продуктовую привязку: к какому продукту Mango относится задача.
4. Тип работы (изменение продукта Mango, база знаний, отраслевая практика,
   внешняя спецификация).
5. Источник каждого утверждения: адрес, место в документе и дословную цитату.
6. Требования (FR), сценарии (UC), нефункциональные требования (NFR),
   обратную совместимость.
7. Открытые вопросы. **Пока хотя бы один вопрос открыт, Release не
   собирается** — ответьте на них или исключите пункт.

Полезные просьбы в диалоге:

- «Перепроверь пункт 4 по базе знаний ещё раз».
- «Покажи противоречия между источниками, если есть».
- «Сведи согласованное в таблицу по пунктам».
- «Что мне сейчас можно сделать дальше? Покажи список действий».

Иногда OpenCode задаёт вопрос с готовыми вариантами ответа (окно выбора в
нижней части экрана): выберите вариант стрелками и нажмите Enter или
введите свой ответ.

## Шаг 4. Получите черновик

1. Переключите агента на **Build** клавишей `Tab`. Под полем ввода должно
   быть написано `Build`. История диалога при переключении сохраняется.
2. **Напишите OpenCode:**

   ```text
   Все пункты согласованы. Пиши черновик в submissions/TASK-0002.json
   по схеме contracts/c-working-bcreq.schema.json, образец формата —
   golden/TASK-0001.json. Моё согласование запиши так:
   проверил и согласовал — <ваши фамилия и имя>, основание — <ссылка на
   комментарий в Jira или «согласовано в диалоге OpenCode <дата>»>.
   Файлы, кроме submissions/TASK-0002.json, не меняй.
   ```

Ваше согласование записывается в черновик **до** машинной проверки: runner
не принимает черновик без отметки о согласовании человеком. Отметка
означает «я проверил пункты 1–7», а не «я одобрил публикацию» — решение о
публикации принимается на [шаге 7](#шаг-7-проверьте-результат-и-примите-решение).

Если агент ответил, что записать файл не может, — проверьте, что выбран
агент **Build**, а не Plan: агенту Plan запись запрещена.

## Шаг 5. Разрешите запись черновика

Перед записью OpenCode показывает запрос разрешения
`△ Permission required` с изменениями файла и тремя вариантами.

- **Проверьте** имя файла в запросе: `submissions/TASK-0002.json` (ваш
  номер). Других файлов в запросе быть не должно.
- Если имя верное — выберите **Allow once** и нажмите Enter.
- Если имя другое — выберите **Reject** (или нажмите `Esc`) и напишите:
  «Пиши только submissions/TASK-0002.json».
- **Allow always** не выбирайте: OpenCode перестанет спрашивать о похожих
  записях до закрытия программы
  ([почему](03-deploy-package.md#как-отвечать-на-запросы-разрешений)).

Запись в любой другой файл пакета [плагин защиты](01-junior-pilot.md#term-guard-plugin)
отклоняет сам, ещё до запроса: агент получает ошибку
`BCREQ guard: OpenCode may write only submissions/TASK-ID.json`.

После записи переключитесь обратно на **Plan** (`Tab`) и попросите:
«Перескажи черновик submissions/TASK-0002.json по пунктам согласования
1–7». Сверьте с тем, что вы согласовали. Если нужна правка — снова Build,
просьба, Allow once.

## Шаг 6. Запечатайте и проверьте задачу

**Действие: «Запечатать и проверить задачу»** (`/bcreq-gate TASK-0002`)

- **Где:** окно OpenCode, поле ввода (агент любой).
- **Команда пакета:**

  ```text
  /bcreq-gate TASK-0002
  ```

- **Что делает:** OpenCode сам, без участия модели, запускает runner:
  [запечатывает](05-commands-reference.md#запечатать-черновик) черновик
  (пересчитывает контрольные суммы — модель их надёжно посчитать не может) и
  [запускает проверку задачи](05-commands-reference.md#запустить-проверку-задачи)
  ([G-mach](01-junior-pilot.md#term-g-mach)). Вывод runner появляется в
  **вашем** сообщении, ниже — пересказ модели.
- **Ожидаемый результат:**

  ```text
  $ python tools/run_task.py seal submissions/TASK-0002.json
  sealed: submissions/TASK-0002.json
  exit code: 0
  $ python tools/run_task.py run TASK-0002 submissions/TASK-0002.json
  TASK-0002: PASS
  exit code: 0
  ```

  или `TASK-0002: FAIL` со строками `ERROR: …` и `exit code: 1`.
- **Проверьте:** итог берите из **вывода runner** в вашем сообщении, а не из
  пересказа модели.

Запечатывание встроено в `/bcreq-gate`, поэтому отдельный шаг «Запечатать
черновик» не нужен ([О-2](01-junior-pilot.md#ограничения-текущей-версии-пакета)).
Если черновик правили после проверки, — это новая попытка под новым TASK ID.

**Если `PASS`** — переходите к шагу 7.

**Если `FAIL`:**

1. Уберите неудачный черновик из `submissions\` командой
   [«Убрать неудачный черновик»](05-commands-reference.md#убрать-неудачный-черновик)
   во вкладке 2 терминала:

   ```powershell
   Move-Item submissions\TASK-0002.json runs\TASK-0002\working.json
   ```

   Черновик сохранится рядом с журналом этого прогона, а папка
   `submissions\` останется чистой для проверки перед отправкой в Git.
2. **Напишите OpenCode** (агент Plan):

   ```text
   Проверка TASK-0002 не прошла, ошибки — в выводе /bcreq-gate выше.
   Объясни простыми словами, что не так, по пунктам. Прежний черновик
   лежит в runs/TASK-0002/working.json. Исправленный черновик будем писать
   под новым номером в submissions/TASK-0003.json.
   ```

3. Повторите шаги 4–6 с номером `TASK-0003`.

Расшифровка частых ошибок — в разделе [Типичные ситуации](#типичные-ситуации).
Если причина непонятна — перейдите в [режим отладки](05-commands-reference.md#режим-отладки).

## Шаг 7. Проверьте результат и примите решение

Машинный `PASS` означает только, что черновик соответствует формату и
правилам. Смысл проверяете вы ([G-human](01-junior-pilot.md#term-g-human)).

1. Попросите OpenCode (агент Plan): «Перескажи runs/TASK-0002/release.json
   по пунктам для согласования». Открыть файл самому можно во вкладке 2:
   `notepad runs\TASK-0002\release.json`.
2. Пройдите чек-лист `evaluation\g-human-checklist.md`:
   - каждый источник действительно прочитан и может использоваться;
   - продуктовая привязка и граница системы соответствуют запросу;
   - FR, UC, NFR, обратная совместимость и смысл Release верны;
   - открытых вопросов нет; публикацию вы одобряете или отклоняете явно.
3. Запишите решение там, где принято в вашей команде (например, комментарием
   в задаче Jira со ссылкой на TASK ID).

До вашего решения Release остаётся кандидатом.

## Диалог с OpenCode: агенты Plan и Build

OpenCode — полноценный собеседник: задавать ему вопросы можно в любой
момент, на русском языке, обычными словами. Команды пакета этому не
мешают: их вывод становится частью диалога.

| Агент | Что OpenCode может | Когда использовать |
|-------|--------------------|--------------------|
| **Plan** | Читать файлы пакета и KB, искать, отвечать; при подключении — читать `kb-readonly` с вашего разрешения. Запись файлов запрещена | Постановка задачи, поиск источников, согласование, вопросы «почему?», разбор ошибок |
| **Build** | То же + записать `submissions\TASK-ID.json` с вашего разрешения | Только когда нужно записать черновик |

Переключение — клавиша `Tab`; имя агента — под полем ввода. Команды
пакета (`/bcreq-start`, `/bcreq-check`, `/bcreq-gate`) сами выполняются
агентом Plan. Ни один агент не может запускать команды: инструмент
`bash` в пакете запрещён. Запись в файлы, кроме `submissions\TASK-ID.json`,
отклоняет [плагин защиты](01-junior-pilot.md#term-guard-plugin) — даже если
выбран Build.

Как задавать вопросы:

- Конкретно: «Почему пункт 3 отнесён к продукту „Речевая аналитика“?
  Покажи цитату».
- С просьбой о форме: «Ответь по пунктам, простыми словами, без JSON».
- С проверкой: «Где это написано? Дай адрес и дословную цитату».
- О следующем шаге: «Что мне делать дальше? Дай список действий с
  командами в скобках».

Встроенные команды OpenCode, которые пригодятся: `/new` — новая сессия,
`/sessions` — вернуться к прошлой, `/compact` — сжать длинный диалог, если
OpenCode начал «забывать» начало, `/undo` — отменить последнее сообщение и
правки агента. Полный список — в
[справочнике](05-commands-reference.md#встроенные-команды-opencode).

## Можно ли подключить внешнюю модель, например DeepSeek

**Технически — да.** В OpenCode есть встроенный провайдер DeepSeek:
`opencode auth login` → **DeepSeek** → ключ API DeepSeek, затем выбор модели
командой `/models`
([документация](https://opencode.ai/docs/providers/)). OpenCode также
позволяет назначить агентам Plan и Build разные модели
([документация](https://opencode.ai/docs/agents/)).

**Для пилота — только с разрешения.** Всё, что вы пишете OpenCode, включая
текст задачи из Jira и выдержки из KB, отправляется выбранной модели. При
внешней модели эти данные уходят за пределы корпоративного контура. Прежде
чем подключать внешнюю модель, получите разрешение ответственного за
информационную безопасность. Без такого разрешения используйте модель
Mango AI ([подключение](02-install.md#подключение-модели-в-opencode)).

Работу пакета с DeepSeek в пилоте не проверяли. Независимо от модели
результат проверки даёт только runner.

## Что ожидать от модели

Модель **может**: вести диалог по шагам, читать файлы пакета и KB, при
подключении — корпоративную базу через `kb-readonly`, объяснять, предлагать
открытые вопросы, писать черновик в `submissions\` (агент Build, с вашего
разрешения), разбирать вывод `/bcreq-gate`, подсказывать следующую команду.

Модель **не может и не должна**:

- запускать команды — их запускаете вы командами пакета или в терминале;
- менять правила, схемы и программы пакета;
- утверждать, что проверка прошла, — смотрите только вывод runner;
- решать за вас вопросы об источниках и публикации.

Когда именно попросить разрешение на запись, решает модель
([О-8](01-junior-pilot.md#ограничения-текущей-версии-пакета)): если запрос
пришёл раньше фразы «пиши черновик», выберите **Reject**.

Модель может ошибаться и уверенно придумывать. Всегда сверяйте цитаты с
источником.

## Разговорные формулировки и термины модели

Пробный диалог в веб-чате показал: модель, не видя файлов пакета,
придумывала шаги процесса и отметки «G-mach ✅», хотя проверка не
запускалась. В пилоте задача ставится в OpenCode внутри папки пакета, а
проверку даёт только runner.

| Как говорят в чате | Что есть в пакете | Как делать |
|--------------------|-------------------|------------|
| «Изучи репозиторий по ссылке» | Папка пакета, в которой запущен OpenCode | Ссылку на репозиторий не давайте; начните с [`/bcreq-start`](#шаг-2-начните-задачу-командой-bcreq-start) |
| «Запускающий промпт» | Команда `/bcreq-start` | Используйте её |
| «Стартуем задачу BCREQ» | Диалог + черновик + `/bcreq-gate` | Задача проверена, только когда runner напечатал `PASS` |
| `RG-BCREQ-v1` | Один процесс «Сформировать бизнес-спецификацию по задаче BCREQ» | Других процессов в пилоте нет |
| Узлы `intake`, `source-scan`, `api-impact`, навыки `skills/` | Нет. Машинные шаги только `validate-working`, `compile`, `validate-release` | Такие «узлы» от модели — выдумка |
| `G-self`, «G-mach ✅» в ответе модели | `G-mach` — только результат runner | Верьте выводу runner, не тексту модели |
| Проекции `V-BIZ`, `V-APPROVE`, `V-DEV`, `V-CONTRACT`; профили `P-…` | Нет | Не выбирайте |
| `product_class=contact-center` | Продуктовая привязка из `taxonomy\mango-products.yaml` | Подтвердите привязку, которую предложит OpenCode (пункт 3 согласования) |
| `RUN-ID`, «Продолжи TASK-X, RUN-Y» | Нет RUN-ID. Повторный запуск с тем же TASK ID запрещён | Исправление — новый TASK ID |
| «Статус», «Покажи источники», «Одобрить» | Не команды пакета, но обычные просьбы OpenCode | Статус — вывод runner и `runs\TASK-ID\`; одобрение — [шаг 7](#шаг-7-проверьте-результат-и-примите-решение) |

Если OpenCode употребляет термин, которого нет в [глоссарии](01-junior-pilot.md#глоссарий)
и в файлах пакета, спросите: «В каком файле пакета это определено?». Нет
файла — это не термин модели.

## Типичные ситуации

| Ситуация | Что это значит | Что делать |
|----------|----------------|------------|
| `ERROR: BASELINE Working digest does not match canonical content` | Черновик изменён после запечатывания | Запустите `/bcreq-gate` с новым TASK ID, сохранив черновик под новым номером |
| `ERROR: EVID-03 evidence checksum does not match the retained excerpt` | Цитата источника изменена после запечатывания | То же |
| `ERROR: BASELINE human approval is required` | В черновике нет отметки о вашем согласовании | Повторите [шаг 4](#шаг-4-получите-черновик) под новым TASK ID |
| `RELEASE unresolved questions block publication` | Остались открытые вопросы | Ответьте на вопросы или исключите пункт; новый черновик — под новым TASK ID |
| `ERROR: run already exists` | Этот TASK ID уже запускался | Новый номер ([почему](05-commands-reference.md#контроль-прогонов-один-task-id--один-прогон)) |
| `ERROR: task ID must match TASK-0001` | Номер не в формате `TASK-NNNN` (например, указан ключ Jira) | Используйте `TASK-` и 4 цифры |
| `ERROR: candidate must be a regular JSON file` сразу после строки `seal` | Черновика `submissions\TASK-ID.json` нет: номер в команде и имя файла расходятся | Проверьте `Get-ChildItem submissions` и повторите с верным номером |
| `ERROR: package hash mismatch` | Файл пакета изменён | Не продолжайте; восстановите пакет повторным копированием, сообщите ответственному |
| `ERROR: OpenCode protection overrides are set` | Защита пакета отключена переменными окружения | Закройте OpenCode, откройте терминал заново, не задавая этих переменных ([список](05-commands-reference.md#чего-в-пилоте-нет)) |
| Агент пишет, что инструмент недоступен или команду запустить нельзя | Модель пыталась запустить команду сама; пакет это запрещает | Ничего не разрешайте; выполните нужную команду сами по инструкции |
| Агент получил ошибку `BCREQ guard: OpenCode may write only submissions/TASK-ID.json` | Модель пыталась записать файл не в `submissions\` | Напомните: «Пиши только submissions/TASK-ID.json» |
| Запрос разрешения на запись пришёл в агенте Plan или до «пиши черновик» | Модель поторопилась | **Reject** и продолжите согласование |
| OpenCode пишет «проверка прошла», а `/bcreq-gate` не запускалась | Модель рассуждает, а не проверяет | Запустите `/bcreq-gate` сами |
| OpenCode привёл цитату, которой нет в источнике | Выдуманный источник | Удалите утверждение или сделайте открытым вопросом |
| Нет подтверждения ни в корпоративной базе, ни в KB | Пробел в источниках | Открытый вопрос, но не догадка |

## Отправка результата в Git

Нужна, только если пакет развёрнут в закрытом (private) runtime-репозитории
и ответственный разрешил отправлять туда черновики. В публичный репозиторий
черновики реальных задач не отправляйте.

1. В `submissions\` должны остаться только черновики, прошедшие проверку.
   Неудачные уберите командой
   [«Убрать неудачный черновик»](05-commands-reference.md#убрать-неудачный-черновик).
2. Во вкладке 2 выполните
   [«Проверить всё перед отправкой»](05-commands-reference.md#проверить-всё-перед-отправкой):
   `python tools/run_task.py verify-ci`. Ожидаемый результат — `PASS` в каждой
   строке.
3. Коммитьте **только** файлы `submissions\TASK-ID.json`. Папки `runs\`,
   `docs\kb\`, `meta-model\` и служебные файлы `.opencode\` Git не отправит
   (`.gitignore`).
4. После отправки CI выполнит ту же проверку (`validate-opencode-package / gate`)
   на Linux и на Windows. Машинный результат принят только при зелёном
   статусе.
