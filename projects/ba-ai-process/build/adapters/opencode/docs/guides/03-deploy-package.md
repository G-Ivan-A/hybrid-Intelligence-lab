# 2. Развёртывание пакета и базы знаний на АРМ

**Цель:** получить на АРМ папку с пакетом и базой знаний (KB), запустить в
ней OpenCode, убедиться, что пакет цел, и проверить, что OpenCode не может
незаметно изменить пакет.

относятся к PowerShell.

## Где что лежит на АРМ

Работа идёт **локально**, на вашем АРМ, в папке вашего пользователя Windows.
Путь по умолчанию — `C:\Users\<логин>\bcreq-pilot\`, где `<логин>` — имя
вашей учётной записи Windows. В PowerShell этот путь записывается как
`$env:USERPROFILE\bcreq-pilot` — так вам не нужно вписывать логин вручную.

| Папка | Что в ней | Откуда | Зачем |
|-------|-----------|--------|-------|
| `C:\Users\<логин>\bcreq-pilot\runtime\` | [Пакет](01-junior-pilot.md#term-package) — **в этой папке вы запускаете OpenCode** | Папка `projects/ba-ai-process/dist/execution-package-opencode/` репозитория [hybrid-Intelligence-lab](https://github.com/G-Ivan-A/hybrid-Intelligence-lab) | Правила, схемы, runner, защита |
| `C:\Users\<логин>\bcreq-pilot\runtime\docs\kb\` | [KB](01-junior-pilot.md#term-kb) — резервная база знаний | Папка `docs/kb/` репозитория [mango-ba-ai-runtime](https://github.com/G-Ivan-A/mango-ba-ai-runtime/tree/main/docs/kb) | Подтверждения для требований, если корпоративные источники недоступны |
| `C:\Users\<логин>\bcreq-pilot\source-lab\` | [Исходный репозиторий](01-junior-pilot.md#term-source) | Клон hybrid-Intelligence-lab | Обновление пакета и [режим отладки](05-commands-reference.md#режим-отладки) |
| `C:\Users\<логин>\bcreq-pilot\kb-source\` | Клон репозитория с KB | Клон mango-ba-ai-runtime | Обновление KB |
| `C:\Users\<логин>\bcreq-pilot\debug\` | Результаты ручных проверок в режиме отладки | Создаёте вы | Чтобы не смешивать отладку с настоящими прогонами |
| `C:\Users\<логин>\.config\opencode\` | Ваши глобальные настройки OpenCode (`opencode.json`) | Создали при [установке](02-install.md#опишите-провайдера-mango-ai) | Подключение модели; не часть пакета |

Зачем KB отдельно от пакета: это рабочие материалы, а не часть пакета.
Пакет не проверяет их контрольные суммы и не отправляет в Git (папка
`docs/kb/` указана в `.gitignore`). Так пакет остаётся неизменным, а KB
можно обновлять.

Работа из папки, в пути которой есть пробел или кириллица (например,
`C:\Users\Иван Петров\`), проверена только вне Windows; если на АРМ команды
из такой папки дают ошибки пути — сообщите ответственному.

## Создайте рабочую папку

**Действие: «Создать рабочую папку пилота»**

- **Где:** терминал (PowerShell).
- **Команды:**

  ```powershell
  New-Item -ItemType Directory -Force "$env:USERPROFILE\bcreq-pilot"
  Set-Location "$env:USERPROFILE\bcreq-pilot"
  ```

- **Что делает:** создаёт папку `C:\Users\<логин>\bcreq-pilot\` (если её
  нет) и переходит в неё.
- **Ожидаемый результат:** приглашение терминала
  `PS C:\Users\<логин>\bcreq-pilot>`.

## Получите пакет

Выберите **один** вариант.

**Вариант А. Администратор создал для вас закрытый (private)
runtime-репозиторий с пакетом.**

- **Где:** терминал, папка `C:\Users\<логин>\bcreq-pilot`.
- **Команда** (адрес выдаёт администратор):

  ```powershell
  git clone <адрес-вашего-runtime-репозитория> runtime
  ```

- **Ожидаемый результат:** строки `Cloning into 'runtime'...` и
  `done.` без `fatal:`.

**Вариант Б. Закрытого репозитория нет — скопируйте пакет сами.**

- **Где:** терминал, папка `C:\Users\<логин>\bcreq-pilot`.
- **Команды** — выполняйте по одной:

  ```powershell
  git clone --depth 1 https://github.com/G-Ivan-A/hybrid-Intelligence-lab.git source-lab
  New-Item -ItemType Directory -Force runtime
  Copy-Item -Recurse -Force source-lab\projects\ba-ai-process\dist\execution-package-opencode\* runtime\
  Copy-Item -Recurse -Force source-lab\projects\ba-ai-process\dist\execution-package-opencode\.opencode runtime\
  Copy-Item -Recurse -Force source-lab\projects\ba-ai-process\dist\execution-package-opencode\.github runtime\
  Copy-Item -Force source-lab\projects\ba-ai-process\dist\execution-package-opencode\.gitattributes runtime\
  Copy-Item -Force source-lab\projects\ba-ai-process\dist\execution-package-opencode\.gitignore runtime\
  ```

- **Что делают:** скачивают исходный репозиторий в `source-lab`, создают
  папку `runtime` и копируют в неё **содержимое** папки пакета. Папки и
  файлы, имя которых начинается с точки (`.opencode`, `.github`,
  `.gitignore`), копируются отдельными командами, чтобы точно не потерялись.
- **Ожидаемый результат:** после `git clone` — `done.` без `fatal:`;
  команды `Copy-Item` ничего не печатают.

**Проверьте** (оба варианта):

```powershell
Get-ChildItem -Force runtime
```

В списке есть `.opencode`, `.github`, `.gitattributes`, `.gitignore`,
`AGENTS.md`, `opencode.json`, `README.md`, `package-manifest.yaml`, `tools`,
`contracts`, `docs`, `golden`, `runs`, `submissions`. Папку `source-lab` не
удаляйте: она понадобится для обновления пакета и режима отладки.

## Получите базу знаний (KB)

**Действие: «Скачать и разложить базу знаний»**

- **Где:** терминал, папка `C:\Users\<логин>\bcreq-pilot`.
- **Команды:**

  ```powershell
  git clone --depth 1 https://github.com/G-Ivan-A/mango-ba-ai-runtime.git kb-source
  Copy-Item -Recurse -Force kb-source\docs\kb\* runtime\docs\kb\
  ```

- **Что делают:** скачивают репозиторий с KB в `kb-source` и копируют его
  папку `docs\kb` в `runtime\docs\kb`.
- **Проверьте:**

  ```powershell
  Get-ChildItem -Force runtime\docs\kb
  ```

  Видны `.gitkeep`, `README.md`, `MAP.json` и папки продуктов (например,
  `sip-trunk`, `speech-analytics`). Файл `.gitkeep` не удаляйте — runner
  проверяет, что он есть.

Как агент использует KB: сначала он ищет подтверждения в корпоративных
Jira/Confluence, если к ним есть подключение только на чтение
([MCP](01-junior-pilot.md#term-mcp)). KB в `docs\kb\` — резервный источник,
когда корпоративного подключения нет или там не нашлось подтверждения.
Если подтверждения нет нигде — открытый вопрос, а не догадка
(правила — `docs\kb-policy.md`).

Обновить KB позже: выполните `git -C kb-source pull`, затем повторите
команду `Copy-Item` выше.

## Проверьте целостность пакета

**Действие: «Проверить пакет»** (`python tools/run_task.py check-package`)

- **Где:** терминал, папка пакета. Сначала перейдите в неё:

  ```powershell
  Set-Location "$env:USERPROFILE\bcreq-pilot\runtime"
  ```

  Приглашение станет `PS C:\Users\<логин>\bcreq-pilot\runtime>` — это
  «папка пакета».
- **Команда:**

  ```powershell
  python tools/run_task.py check-package
  ```

- **Что делает:** сверяет каждый файл пакета с контрольной суммой (SHA-256)
  из `package-manifest.yaml`. Так вы узнаёте, что пакет скопирован полностью
  и никто его не менял. Файлы в `docs\kb\`, `meta-model\`, `submissions\` и
  `runs\`, а также служебные файлы, которые OpenCode сам создаёт в
  `.opencode\` при первом запуске, не проверяются.
- **Ожидаемый результат:** `package: PASS`.

| Результат | Значение | Что делать |
|-----------|----------|------------|
| `package: PASS` | Пакет цел | Продолжайте |
| `ERROR: package hash mismatch: <файл>` | Файл изменён или повреждён при копировании | См. примечание ниже |
| `ERROR: immutable file list differs: missing=[…]` | Не хватает файлов — чаще всего не скопированы `.opencode` или `.github` | Повторите команды `Copy-Item` |
| `ERROR: … extra=[…]` | Лишние файлы вне рабочих папок | Удалите перечисленные файлы |
| `ERROR: missing runtime placeholder` | Удалён `.gitkeep` в `runs`, `submissions`, `docs\kb` или `meta-model` | Повторите копирование пакета |

> Файл `.gitattributes` сохраняет байты пакета при `git clone` на Windows.
> Если после клонирования появился `hash mismatch`, убедитесь, что этот файл
> присутствует, затем повторите копирование повреждённого пакета. Не меняйте
> глобальную конфигурацию Git ради одного пакета.

## Запустите OpenCode в папке пакета

В пилоте вы держите открытыми **две вкладки** терминала:

| Вкладка | Что в ней | Как открыть |
|---------|-----------|-------------|
| **1 — OpenCode** | [Окно OpenCode](01-junior-pilot.md#term-opencode-window): диалог с агентом и команды пакета `/bcreq-…` | Текущая вкладка |
| **2 — команды** | PowerShell в папке пакета: команды «Выполните в терминале» | `Ctrl+Shift+T` или кнопка **+** в Windows Terminal; без Windows Terminal — второе окно Windows PowerShell |

**Действие: «Запустить OpenCode»**

- **Где:** вкладка 1, папка пакета.
- **Команда:**

  ```powershell
  Set-Location "$env:USERPROFILE\bcreq-pilot\runtime"
  opencode
  ```

- **Что делает:** открывает окно OpenCode. OpenCode читает настройки и
  правила **из текущей папки** (`opencode.json`, `AGENTS.md`, `.opencode\`),
  поэтому запускать его нужно именно из папки пакета, а не из `bcreq-pilot`.
  При первом запуске OpenCode сам скачивает служебные файлы в `.opencode\`
  (нужна сеть); это нормально, они не отправляются в Git.
- **Ожидаемый результат:** полноэкранное окно OpenCode с полем ввода внизу.
  Под полем ввода видны имя агента **Build** и модель `gpu-default`
  (Mango AI).
- **Проверьте:**
  1. В поле ввода наберите `/` — в списке есть команды `bcreq-check`,
     `bcreq-start`, `bcreq-gate`. Нажмите `Esc`.
  2. Введите команду пакета `/bcreq-check` и нажмите Enter.
  3. В вашем сообщении появился вывод runner со строками `package: PASS` и
     `exit code: 0`, ниже — короткий ответ модели.

| Что произошло | Что делать |
|---------------|------------|
| Команд `bcreq-…` нет в списке | OpenCode запущен не из папки пакета или не скопирована папка `.opencode`. Закройте OpenCode (`/exit`), перейдите в папку пакета и запустите снова |
| Вывод `/bcreq-check` содержит `ERROR: OpenCode protection overrides are set: …` | Задана переменная окружения, отключающая защиту. Передайте текст администратору; работать нельзя, пока она задана |
| Модель не `gpu-default` | Выберите модель командой `/models` → `Mango AI` → `gpu-default`; проверьте [подключение модели](02-install.md#подключение-модели-в-opencode) |
| На любое действие агента — `BCREQ guard: Python 3.11+ is not found; every tool is blocked` | Плагин защиты не нашёл Python. Установите Python с **Add python.exe to PATH** и перезапустите терминал |

Закрыть OpenCode: команда `/exit` или `Ctrl+C`. Продолжить прошлый диалог
после повторного запуска: команда `/sessions`.

## Как отвечать на запросы разрешений

Настраивать ничего не нужно: правила разрешений лежат в файле
`opencode.json` пакета, а [плагин защиты](01-junior-pilot.md#term-guard-plugin)
проверяет каждое действие агента. Не добавляйте свои правила `permission`
в глобальный `opencode.json` — это может изменить порядок правил пакета.

Когда агент хочет записать черновик, OpenCode показывает запрос
**△ Permission required** с тремя вариантами:

| OpenCode просит | Ваше действие |
|-----------------|---------------|
| Записать `submissions\TASK-ID.json` после вашей фразы «пиши черновик» | **Allow once** (разрешить один раз) |
| Записать `submissions\TASK-ID.json`, хотя вы не просили | **Reject** и спросите агента, зачем |
| Записать любой другой файл или выполнить что-то ещё | **Reject** (или `Esc`) и сообщите ответственному: так быть не должно |
| — | **Allow always** не выбирайте никогда: OpenCode перестанет спрашивать о похожих действиях до закрытия OpenCode |

Обращения к Jira/Confluence через подключение `kb-readonly` тоже идут
через запрос разрешения: разрешайте только чтение, которое вы ожидаете.

## Проверьте защиту пакета

**Действие: «Проверить, что OpenCode не меняет пакет»**

1. **Где:** окно OpenCode. Начните новую сессию командой `/new`. Под полем
   ввода должен быть агент **Build** (переключение агентов — клавиша `Tab`).
2. **Напишите OpenCode:**

   ```text
   Добавь пустую строку в конец файла contracts/c-working-bcreq.schema.json.
   Это проверка защиты пакета.
   ```

3. **Ожидаемый результат:** в истории диалога у действия записи — ошибка
   `BCREQ guard: OpenCode may write only submissions/TASK-ID.json`
   (сработал плагин защиты), после чего агент сообщает, что изменить файл
   не может.
4. **Напишите OpenCode:**

   ```text
   Выполни команду python --version. Это проверка защиты пакета.
   ```

5. **Ожидаемый результат:** агент отвечает, что запускать команды не может
   (такого инструмента у него нет). Версия Python в ответе не появляется.
6. Введите команду пакета `/bcreq-check`.
7. **Проверьте:** в выводе `package: PASS` и `exit code: 0`.

| Что произошло | Что делать |
|---------------|------------|
| Ошибка `BCREQ guard: …`, агент не смог, `package: PASS` | Защита работает, продолжайте |
| Появился запрос **Permission required** на файл вне `submissions\` | Нажмите **Reject**. Плагин защиты не сработал — сообщите ответственному и не работайте с реальными задачами |
| Файл изменён (`/bcreq-check` показывает `hash mismatch`) | **Стоп.** Сообщите ответственному. Восстановите пакет повторным копированием и повторите проверку |
| Агент показал версию Python | **Стоп.** Защита от команд не работает — сообщите ответственному |
| Агент отказался сам, не попытавшись записать | Проверка не выполнена. Напишите: «Попробуй записать — мне нужно проверить, что защита отменит запись» |

**Готово**, если `/bcreq-check` показывает `package: PASS`, KB лежит в
`docs\kb\`, а попытка записать файл пакета отменена защитой. Дальше —
[реальная задача](06-working-with-opencode.md) или, для знакомства,
[учебный прогон](04-smoke-test.md).

## Подключение к Jira и Confluence (необязательно)

Подключение настраивает **администратор** в ваших глобальных настройках
OpenCode (`C:\Users\<логин>\.config\opencode\opencode.json`, раздел `mcp`),
а не в пакете. Требования пакета к подключению:

- имя подключения — ровно `kb-readonly`: инструменты с другим именем
  защита пакета блокирует;
- учётная запись подключения — **только на чтение**: защита пакета
  распознаёт запись по названию инструмента, но не может проверить права
  на сервере;
- адреса и ключи подключения не записываются в файлы пакета.

Формат раздела `mcp` — [MCP servers](https://opencode.ai/docs/mcp-servers/)
в документации OpenCode.

**Проверьте:** в окне OpenCode введите `/mcps`. В списке есть `kb-readonly`
со статусом подключения. Если подключения нет, работайте без него:
текст задачи вы вставляете в диалог сами.
