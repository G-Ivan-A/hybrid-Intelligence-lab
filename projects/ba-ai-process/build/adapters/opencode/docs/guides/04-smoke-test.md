# 3. Учебный прогон (необязательно)

**Цель:** один раз увидеть весь путь на готовом учебном примере `TASK-0001`
без корпоративных данных: как агент объясняет задачу, как запускается
проверка и как выглядит успешный результат.

Этот шаг **не обязателен** и не открывает доступ к реальным задачам: после
[развёртывания](03-deploy-package.md) можно сразу переходить к
[реальной задаче](06-working-with-opencode.md).

## Что такое учебный пример

- В пакете есть папка [`golden\`](01-junior-pilot.md#term-golden) с файлом
  `TASK-0001.json`. Это **готовый черновик** BCREQ Working по вымышленной
  задаче «клиенты хотят выгружать журнал звонков». Его подготовили авторы
  пакета; ссылки вида `example.test` — заглушки, а не корпоративные страницы.
- Файлы в `golden\` менять нельзя: это эталон, по которому пакет проверяет
  сам себя.
- [Runner](01-junior-pilot.md#term-runner) проверяет черновики, которые лежат
  в папке [`submissions\`](01-junior-pilot.md#term-submissions) — папке
  «ваших» задач. Поэтому для учебного прогона вы кладёте **копию** эталона в
  `submissions\` и дальше работаете с ней так же, как с реальной задачей.

В реальной задаче копировать ничего не нужно: черновик в `submissions\`
пишет агент по вашим данным ([Работа с агентом](06-working-with-opencode.md)).

## Шаг 1. Подготовьте учебный пример

**Действие: «Подготовить учебный пример»**

- **Где:** вкладка 2 [терминала](01-junior-pilot.md#term-terminal), папка
  пакета `C:\Users\<логин>\bcreq-pilot\runtime`.
- **Команда:**

  ```powershell
  Copy-Item golden\TASK-0001.json submissions\TASK-0001.json
  ```

- **Что делает:** копирует файл учебного черновика из `golden\` в
  `submissions\` под тем же именем. Эталон остаётся нетронутым.
- **Ожидаемый результат:** команда ничего не печатает.
- **Проверьте:**

  ```powershell
  Get-ChildItem submissions
  ```

  В списке есть `TASK-0001.json`.

## Шаг 2. Попросите OpenCode объяснить пример

- **Где:** [окно OpenCode](01-junior-pilot.md#term-opencode-window)
  (вкладка 1). Начните новую сессию командой `/new` и переключитесь на
  агента **Plan** клавишей `Tab` (только разговор, файлы не меняются).
- **Напишите OpenCode:**

  ```text
  Это учебный пример, а не реальная задача.
  Открой учебный черновик submissions/TASK-0001.json и объясни простыми словами,
  без технических терминов:
  1. Какую задачу клиента он описывает.
  2. Что входит в изменение и что не входит.
  3. К какому продукту это относится.
  4. Какие требования получились.
  5. На какой источник опирается каждое требование.
  Отвечай нумерованным списком.
  ```

- **Ожидаемый результат:** нумерованный ответ: задача — выгрузка журнала
  звонков существующими клиентами; входит выгрузка отчёта, не входит
  формирование внешнего вида отчётов (report rendering); источник — один
  документ-заглушка `example.test`.
- **Проверьте:** OpenCode не придумал других источников. Если сомневаетесь,
  спросите: «Покажи дословную цитату из черновика для пункта 5».

## Шаг 3. Запустите проверку задачи

**Действие: «Запечатать и проверить задачу»** (`/bcreq-gate TASK-0001`)

- **Где:** окно OpenCode, поле ввода.
- **Команда пакета:**

  ```text
  /bcreq-gate TASK-0001
  ```

- **Что делает:** OpenCode сам (без участия модели) запускает runner:
  сначала [запечатывает](01-junior-pilot.md#term-seal) черновик, затем
  проверяет целостность пакета, по очереди запускает три машинные проверки
  черновика ([G-mach](01-junior-pilot.md#term-g-mach)), собирает
  [Release](01-junior-pilot.md#term-release) и записывает
  [журнал прогона](01-junior-pilot.md#term-trace) в `runs\TASK-0001\`.
  Модель затем только пересказывает вывод.
- **Ожидаемый результат:** через несколько секунд в **вашем** сообщении —
  вывод runner:

  ```text
  $ python tools/run_task.py seal submissions/TASK-0001.json
  sealed: submissions/TASK-0001.json
  exit code: 0
  $ python tools/run_task.py run TASK-0001 submissions/TASK-0001.json
  TASK-0001: PASS
  exit code: 0
  ```

  Ниже — ответ модели с итогом и следующим шагом.
- **Проверьте:** во вкладке 2 выполните

  ```powershell
  Get-ChildItem runs\TASK-0001
  ```

  В списке есть `trace.jsonl`, `release.json`, `release-manifest.json`.

То же самое без OpenCode — во вкладке 2:
`python tools/run_task.py run TASK-0001 submissions/TASK-0001.json`
(учебный пример уже запечатан авторами пакета).

Если вместо `PASS` появилось `FAIL` или `ERROR:` — пакет повреждён. Не
продолжайте, передайте текст вывода ответственному.

## Шаг 4. Посмотрите результат

- Файл `runs\TASK-0001\release.json` — собранный Release. Он пока
  **кандидат**: окончательное решение за человеком
  ([G-human](01-junior-pilot.md#term-g-human)). Открыть его можно в Блокноте:
  `notepad runs\TASK-0001\release.json` (вкладка 2).
- **Напишите OpenCode** (агент Plan):

  ```text
  Прочитай runs/TASK-0001/release.json и перескажи по пунктам, что получит клиент.
  ```

Разбор журнала `trace.jsonl` нужен в [режиме отладки](05-commands-reference.md#как-читать-журнал-прогона-trace);
для учебного прогона достаточно строки `TASK-0001: PASS`.

## Повторить учебный прогон

Повторный запуск с номером `TASK-0001` runner отклонит:
`ERROR: run already exists` — так он защищает журнал от перезаписи
([один TASK ID — один прогон](05-commands-reference.md#контроль-прогонов-один-task-id--один-прогон)).
Только для учебного примера можно удалить результат (вкладка 2) и
запустить заново командой `/bcreq-gate TASK-0001`:

```powershell
Remove-Item -Recurse runs\TASK-0001
```

Для реальных задач папки `runs\` не удаляйте — берите новый TASK ID.
