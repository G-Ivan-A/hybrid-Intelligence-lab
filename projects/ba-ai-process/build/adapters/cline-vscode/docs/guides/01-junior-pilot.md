# Первый пилот BCREQ для бизнес-аналитика

Нужны разрешённый рабочий компьютер с VS Code, Git, Python 3.11 или новее,
доступом к Mango AI и личным API-ключом. Локальная видеокарта для модели не
нужна. Сначала используйте только публичный синтетический пример.

1. Установите [VS Code](https://code.visualstudio.com/download) и официальное
   [расширение Cline](https://docs.cline.bot/getting-started/installing-cline).
   Откройте скопированный пакет как корневую папку проекта. В терминале VS Code
   выполните `python3 --version` и `python3 tools/run_task.py check-package`.
   Продолжайте только если пакет показывает `PASS`.
2. В настройках Cline выберите **OpenAI Compatible**. Введите Base URL,
   выданный администратором AI Core, личный ключ `sk-…` и модель `gpu-default`.
   Укажите Context Window `114688`, Max Output Tokens `16384`, отключите
   поддержку изображений для пилота. Сохраняйте ключ только в хранилище
   учётных данных Cline: не вставляйте его в чат, файлы и снимки экрана.
   Для выданного URL может понадобиться корпоративная сеть или VPN.
3. В Cline Feature Settings включите hooks. На macOS/Linux проверьте, что
   `.clinerules/hooks/TaskStart`, `TaskResume` и `PreToolUse` исполняемы
   (`chmod +x .clinerules/hooks/*`). Попросите Cline прочитать `AGENTS.md`,
   затем предложите изменить `contracts/c-working-bcreq.schema.json`. Hook
   должен заблокировать запись; после проверки отмените эту задачу. Если hook
   не сработал, остановитесь и попросите администратора проверить версию Cline,
   ОС и настройку hooks. Поддержку hooks на Windows нужно подтвердить отдельно
   на целевом АРМ до пилота.
4. Администратор отдельно настраивает в Cline MCP Servers одобренное подключение
   Jira/Confluence **только на чтение** и проверяет доступ к тестовому ресурсу.
   Пока его нет, используйте разрешённые файлы `docs/kb/` по
   `docs/kb-policy.md`. Синтетическому примеру корпоративный источник не нужен.
5. Скопируйте пример командой `cp golden/TASK-0001.json submissions/TASK-0001.json`. Попросите Cline объяснить поля BCREQ Working
   в этом файле и назвать источник с точным якорем. `example.test` здесь
   синтетическая заглушка, а не прочитанная корпоративная страница. Сверьте
   ответ с файлом.
   Затем в терминале выполните `python3 tools/run_task.py run TASK-0001 submissions/TASK-0001.json`.
6. Проверьте строку `TASK-0001: PASS`. Откройте
   `runs/TASK-0001/trace.jsonl`: три машинных шага должны иметь состояние
   `script_invoked` и exit code `0`, затем идёт `contract_mode` для проверки
   человеком. Прочитайте `release.json` и `release-manifest.json` в той же
   папке. `FAIL` или `step_skipped` останавливает задачу; исправьте кандидат
   и используйте новый TASK ID для новой попытки.
7. Для PR в закрытом runtime-репозитории коммитьте только разрешённый Working
   JSON в `submissions/`. Машинный результат принимается после обязательного
   статуса CI `validate-cline-package / gate`. Источники, права на публикацию,
   продуктовую привязку и смысл результата БА проверяет отдельно. До этого
   Release остаётся кандидатом.
