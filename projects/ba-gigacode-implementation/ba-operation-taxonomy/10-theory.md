# Теория: почему прежние «операции» операциями не были

## 1. Что именно сломано

| Дефект | Измерение | Следствие |
| --- | --- | --- |
| `D3` | 7 значений из 13 производят более одного класса выхода; `documentation` — шесть: `business-alignment-pack`, `constraints-section`, `feature-spec-kk`, `fr-section`, `meeting-summary`, `tz-contract` | по имени операции невозможно предсказать результат, значит невозможен ни контракт, ни машинная проверка выхода |
| `D4` | 8 значений из 13 перечисляют разнородные результаты в определении: `understanding` — «извлекает термины, цели, неявные допущения; формирует уточняющие вопросы» | определение описывает набор работ, а не одну работу; извлечение и порождение вопроса — разные когнитивные действия с разной проверкой |

Оба дефекта — один корень: словарь строился как **рубрикатор для навигации по
корпусу**, а не как контракт исполнения. Для навигации тринадцати широких
рубрик достаточно; для исполнения агентом — нет, потому что агент получает на
вход имя операции и должен из него вывести форму результата.

Обратная сторона тоже названа: дробление до микродействий («прочитать»,
«нажать») даёт словарь, из которого невозможно собрать смысл. Правильная
гранулярность лежит между рубрикой и нажатием клавиши, и её нужно задать
критериями, а не примерами.

## 2. Критерии атомарности `OA-1`–`OA-6`

| Критерий | Формулировка | Как проверяется |
| --- | --- | --- |
| `OA-1` | **Один контракт выхода.** Операция производит ровно один класс результата с одной схемой. Два класса — две операции. | машинно: схема выхода объявлена и единственна |
| `OA-2` | **Нет ветвления.** Внутри операции нет условия, меняющего её выход по классу. Условие — признак подпроцесса (`SB-5`). | машинно: контракт не содержит альтернативных выходов |
| `OA-3` | **Семантическая завершённость.** Результат осмыслен вне операции: его можно назвать существительным предметной области («перечень сущностей», «вердикт атомарности»), а не действием с интерфейсом. | ревью по тесту именования |
| `OA-4` | **Один тип когнитивной работы.** Операция принадлежит ровно одному классу из пяти (§3). Извлечение и порождение в одном имени запрещены. | машинно: класс объявлен и единственный |
| `OA-5` | **Воспроизводимость в объявленном допуске.** Повторный запуск на том же входе даёт результат, совпадающий по объявленной мере: для извлечения — множество элементов, для оценки — значение в объявленном интервале. | эксперимент, метрика `MO-2` |
| `OA-6` | **Один исполнитель, без передачи.** Операция не содержит ожидания внешнего ответа. Ожидание ответа Заказчика — это ребро маршрута между операциями, а не их часть. | машинно: контракт не объявляет внешнего события |

`OA-6` — прямое следствие определения актора: операция выполняется одним
актором, а передача другому актору есть переход маршрута, который должен быть
виден в следе.

## 3. Пять когнитивных классов

Классы различаются не предметом, а **типом работы над смыслом** — тем, откуда
берётся информация в выходе. Это и определяет пригодный механизм контроля.

| Класс | Откуда берётся содержание выхода | Механизм контроля по умолчанию | Риск |
| --- | --- | --- | --- |
| `extract` — извлечение | целиком из входа; нового содержания не появляется | `G6` внешняя сверка с источником | пропуск элемента |
| `transform` — преобразование | из входа, меняется форма или структура, не смысл | `G2` схема выхода | потеря элемента при переносе |
| `generate` — порождение | появляется новое содержание, которого во входе не было | `G6` при наличии источника, `G5` при выходе вовне | галлюцинация |
| `check` — проверка | суждение о соответствии входа объявленному критерию | `G2` схема вердикта + `G6` для критериев, выразимых кодом | ложное «соответствует» |
| `assess` — оценка и выбор | упорядочение или выбор из объявленного множества | `G1` инструкция + `G5` при необратимости выбора | немотивированный выбор |

**Почему пять, а не больше.** Класс включается в перечень, только если он
меняет механизм контроля. `transform` и `extract` разделены, потому что
извлечение проверяется сверкой с источником, а преобразование — схемой.
`check` и `assess` разделены, потому что вердикт проверяется на
воспроизводимость, а выбор — на обоснованность. Класс, не меняющий проверку, в
таксономию не вносится (Anti-Inflation).

## 4. Контракт операции

Операция определена шестёркой полей. Отсутствие любого поля означает, что
операция не определена и не может быть вызвана.

| Поле | Содержание |
| --- | --- |
| `имя` | глагольная форма предметной области в нижнем регистре через дефис |
| `класс` | одно из пяти значений §3 |
| `вход` | класс входного объекта и обязательные поля |
| `выход` | единственный класс результата и его схема (`OA-1`) |
| `условие отказа` | случай, в котором операция обязана вернуть отказ, а не результат «по возможности» |
| `ярус` | нижняя граница механизма контроля, ниже которой выход не принимается |

**Условие отказа — не формальность.** Именно оно отличает операцию от промпта:
операция, которая на пустом или нерелевантном входе обязана вернуть отказ, не
породит правдоподобный вымысел. Отсутствие объявленного отказа — главный
источник галлюцинаций в порождающих классах.

## 5. Отношение к навыку

Правила `SB-0`–`SB-9`
([`ba-process-taxonomy/10-theory.md`](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/projects/ba-gigacode-implementation/ba-process-taxonomy/10-theory.md), §4)
задают `Процесс → Подпроцесс (1:N) → Операция (1:N)`. Из них для этого модуля
важны два следствия.

1. **Операция не принадлежит навыку.** Одна операция вызывается многими
   навыками: `check-atomicity` работает и в детализации ФТ, и в верификации.
   Словарь операций — общий ресурс, словарь навыков — принадлежность процесса.
2. **Порядок операций — свойство навыка.** Операция не знает, что было до неё:
   всё, что ей нужно, объявлено во входе. Это условие переиспользования и
   условие машинной проверки.

## 6. Границы

- Критерии `OA-1`–`OA-6` проверены на 33 навыках одной предметной области.
  Утверждение о достаточности критериев вне её не делается.
- `OA-5` объявляет воспроизводимость, но допуск для порождающих классов не
  измерен: эмпирика собирается на первых прогонах (`MO-2`).
- Ярусы в §3 — значения по умолчанию; конкретный ярус операции назначается в
  каталоге и может быть выше, но не ниже.
