# Навык: приоритизация вопросов

## Когда применять

Вход — `A-QUEST` без порядка; выход — тот же перечень с полем `rank` и
обоснованием порядка у каждого вопроса.

## Предусловия

1. Перечень вопросов непуст и проходит `contracts/c-quest.schema.json`.
2. У каждого вопроса известна значимость его неоднозначности в ядре.
3. Шкала оценки объявлена ниже и не заменяется на ходу.

## Шаги

1. `score-item` — оцени каждый вопрос по трём признакам:
   - `blocking` — число утверждений ядра, зависящих от ответа;
   - `severity` — значимость исходной неоднозначности (`blocker` = 3,
     `major` = 2, `minor` = 1);
   - `cost` — 1, если ответ известен одному владельцу продукта, 2 — если
     требует согласования.
2. `rank-items` — упорядочи по убыванию `severity × blocking / cost`. Правило
   порядка записывается вместе с результатом: без него два прогона одного
   перечня неразличимы при разборе.
3. `generate-rationale` — у каждого вопроса объясни его место ссылкой на
   значения признаков, а не общими словами.

## Обязательные слоты выхода

| Слот | Каноническая подпись | Обязательность | Причина пустоты |
| --- | --- | --- | --- |
| `questions[].rank` | Порядковый номер | обязателен | нет |
| `questions[].rank_rationale` | Обоснование порядка | обязателен | нет |
| `ranking_rule` | Правило порядка | обязателен | нет |

## Самопроверка (G-self)

- Каждому вопросу присвоен уникальный `rank` — да/нет.
- Обоснование каждого места ссылается на значения признаков — да/нет.
- Правило порядка применено ко всему перечню без исключений — да/нет.
- Состав вопросов не изменился: ни один не добавлен и не удалён — да/нет.

## Отказ

Остановись и верни вопрос человеку, если:

- перечень вопросов пуст;
- шкала не объявлена или значения признаков неизвестны хотя бы для одного
  вопроса: порядок «на глаз» делает приоритизацию невоспроизводимой.
