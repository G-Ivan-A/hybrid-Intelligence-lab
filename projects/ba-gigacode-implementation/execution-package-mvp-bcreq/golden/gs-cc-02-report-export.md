# Эталон GS-CC-02: выгрузка отчёта по обработке обращений

Второй эталон проверяет правило `R-4`: короткий документ содержит **те же**
обязательные слоты, что и полный, — короче, но не меньшим числом слотов.

## Вход

`A-IN`, `raw`, источник `SRC-01` — письмо супервизора:

> «Нужна выгрузка по обработке обращений за период: сколько принято, среднее
> время обработки, кто из операторов сколько обработал. Настроек никаких не
> надо, просто фиксированный отчёт раз в сутки на почту.»

Реестр продуктов: маркер `А`, класс `contact-center`, atomic function
`handling-report-export`, профиль `P-NO-SETTINGS`, владелец — супервизор.

## Ожидаемая структура выхода

- Класс артефакта `A-BCREQ`, класс формата `F-SHORT`.
- Присутствуют все 14 слотов скелета — ни один не опущен из-за краткости.
- Заполнены: `S-GLOSSARY`, `S-PROBLEM`, `S-SCOPE`, `S-SOLUTION`, `S-FR`,
  `S-SCENARIO`, `S-AC`, `S-LIMITS`, `S-OPEN`, `S-TRACE`.
- Пусты с причиной: `S-SETTINGS` («нет по продукту», профиль `P-NO-SETTINGS`),
  `S-UI` («нет в источнике»), `S-NFR` («в источнике нет требований к качеству»),
  `S-INTEGRATION` («нет по продукту»).
- `S-OPEN` непуст: период выгрузки и адресат рассылки в источнике не названы;
  каждый открытый вопрос имеет адресата.
- `S-GLOSSARY` содержит `AHT` — показатель назван термином словаря, а не
  речевым «среднее время».

## Ожидаемое содержание (не проверяется машинно)

Проблема: супервизор не имеет регулярного среза по обработке обращений и
собирает данные вручную. Требования: суточное формирование отчёта с числом
принятых обращений, `AHT` и разбивкой по операторам; доставка на почту.
Открытые вопросы: за какой период считается «сутки» и кому уходит рассылка.

## Чего в эталоне намеренно нет

- Формата файла и структуры колонок: это уровень `A-FR`, а не `A-BCREQ`.
- Домысленного значения периода: отсутствующий факт уходит в `S-OPEN`, а не
  подставляется.
- Раздела `S-OTHER`.
