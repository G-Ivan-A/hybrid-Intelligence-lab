# Негативный эталон GS-CC-NEG-04: `IVR` против автоинформатора

Пара взята из словаря домена (`TRM-IVR` ↔ `TRM-ANNOUNCER`). Подмена убирает из
требования ветвление, то есть меняет объём работ, а не формулировку.

## Вход

`A-IN`, `raw`, источник `SRC-01` — расшифровка встречи:

> «Поставьте на нерабочее время сообщение: пусть говорит график работы и что
> можно оставить заявку. Если человек хочет — пусть оставит.»

Реестр продуктов: маркер `А`, класс `contact-center`, atomic function
`after-hours-greeting`, профиль `P-SETTINGS`, владелец — руководитель
контакт-центра.

## Словарь связанных терминов

| Термин | Значение словаря | Смежное понятие | Почему подмена опасна |
| --- | --- | --- | --- |
| `IVR` | сценарий с приёмом ввода абонента и ветвлением | `Автоинформатор` | требование получает ветвление, которого источник не подтверждает |
| `Автоинформатор` | однонаправленное воспроизведение сообщения | `IVR` | «пусть оставит заявку» требует ввода, которого у автоинформатора нет |

Источник содержит оба признака сразу: «пусть говорит» — воспроизведение,
«если человек хочет — пусть оставит» — ввод и ветвление.

## Ожидаемый отказ

- узел `context-extraction-contact-center` отказывает: сценарий описан
  признаками двух разных понятий словаря одновременно;
- лист прогона фиксирует `verdict: refused` и `outcome: refused`;
- `A-BCREQ` не формируется.

Допустимая форма прохождения — явный статус пары в `S-LIMITS`:

| Понятие | Статус | Основание |
| --- | --- | --- |
| `IVR` | включено | «если человек хочет — пусть оставит» требует приёма ввода |
| `Автоинформатор` | исключено | воспроизведение без ввода не покрывает оставление заявки |

## Чего в эталоне намеренно нет

- Разбиения на два требования «сообщение» и «заявка» без решения Заказчика:
  разбиение — проектное решение, а не извлечение факта из источника.
