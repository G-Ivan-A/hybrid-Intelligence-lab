# Навык: формирование вопросов Заказчику

## Когда применять

Вход — `A-CORE` в состоянии `needs-clarification`; выход — `A-QUEST`: перечень
вопросов, каждый из которых снимается одним фактом.

## Предусловия

1. Ядро содержит непустой перечень неоднозначностей с видом и значимостью.
2. У каждой неоднозначности есть идентификатор `AMB-NN`.
3. Адресат вопроса известен из реестра продуктов (`owner`).

## Шаги

1. `generate-question` — по каждой неоднозначности сформулируй ровно один
   вопрос. Вопрос отвечается одним фактом: «Сколько секунд составляет порог
   ожидания?» — да; «Как должна работать очередь?» — нет, такой вопрос
   возвращает новую сессию выявления вместо ответа.
2. `deduplicate-items` — слей вопросы, отличающиеся только формулировкой;
   сохрани связь слитого вопроса со всеми исходными неоднозначностями.
3. `check-schema` — проверь перечень против `contracts/c-quest.schema.json`.

## Обязательные слоты выхода

| Слот | Каноническая подпись | Обязательность | Причина пустоты |
| --- | --- | --- | --- |
| `questions[]` | Вопросы | обязателен, непуст | нет |
| `questions[].ambiguity_id` | Неоднозначность | обязателен | нет |
| `questions[].addressee` | Адресат | обязателен | нет |
| `questions[].text` | Формулировка | обязателен | нет |

## Самопроверка (G-self)

- Каждый вопрос ссылается на существующую неоднозначность ядра — да/нет.
- Каждый вопрос отвечается одним фактом — да/нет.
- Ни один вопрос не содержит собственного предположения о правильном ответе — да/нет.
- У каждого вопроса объявлен адресат — да/нет.
- Перечень проходит `contracts/c-quest.schema.json` — да/нет.

## Отказ

Остановись и верни вопрос человеку, если:

- перечень неоднозначностей пуст: формировать нечего, и маршрут должен был уйти
  в ветвь формирования требования;
- неоднозначность сформулирована так, что одного факта для её снятия не хватает:
  такая запись — дефект предыдущего узла, а не материал для вопроса;
- адресат вопроса не определён ни одним владельцем продукта.
