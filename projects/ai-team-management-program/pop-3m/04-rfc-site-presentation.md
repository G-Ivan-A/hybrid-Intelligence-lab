# RFC: сайт-презентация программы «ИИ в работе с командой»

## 1. Цель

Преобразовать четыре артефакта программы в публичный одностраничный сайт для
стейкхолдеров: спонсора, руководителя T&D, службы информационной безопасности
и будущих участников. Сайт продаёт идею программы за 3 минуты чтения и ведёт
к одному действию — запросу детального бюджета.

| Артефакт | Что берёт сайт |
| --- | --- |
| `01-project-summary.md` | Хук, бизнес-цель, ценность для руководителя, аргументы «Почему так» |
| `02-project-passport.md` | Таймлайн 12 недель, зоны данных, уровни оценки L1–L4 |
| `03-appendix.md` | Доказательная база, роли команды, кандидаты |
| `05-detailed-economics.md` | Не публикуется; высылается по запросу из формы «Запросить детальный бюджет» |

## 2. Структура сайта

Разделы сайта построены по пути стейкхолдера «зацепить → показать → доказать →
познакомить → запросить», а не по файлам репозитория.

| № | Раздел | Содержание | Источник | Интерактив |
| --- | --- | --- | --- | --- |
| 1 | Лендинг-хук | Заголовок «11 недель от ручной рутины к собственным ИИ-агентам»; подзаголовок — бизнес-цель; 4 счётчика: 91 а.ч., 3 очных блока, 80% практики, 80% участников с прототипом | Резюме | Счётчики анимируются при прокрутке; кнопка «Запросить детальный бюджет» в первом экране |
| 2 | «Что получает руководитель» | 4 карточки: свои ИИ-агенты, прототип дашборда, классификация данных, план 30/60/90 | Резюме | Карточка раскрывает пример результата |
| 3 | «Светофор данных» | Зелёная, жёлтая, красная зона и выбор модели в интерфейсе JustAI | Паспорт, уровень 2 | Переключатель зоны показывает, какую модель выбирает руководитель |
| 4 | Интерактивный таймлайн | 12 недель (0–11) на одной оси: очные блоки крупными узлами, онлайн-недели — малыми; три фазы: «Агенты», «Штурм», «Изменения» | Паспорт, уровень 3 | Клик по неделе открывает темы лекций, формат, а.ч., кто ведёт, результат недели; фильтр «очно / онлайн» |
| 5 | «Почему это работает» | 4 карточки-факта: 66 дней на привычку, перенос 0,92 против 0,45, 2 очных дня в месяц, 1 инструмент | Приложение [1], [3] | Ссылка на первоисточник под каждой цифрой |
| 6 | «Как мы измеряем результат» | Уровни L1–L4 с целевыми значениями | Паспорт, уровень 5 | Ступенчатая диаграмма L1 → L4 |
| 7 | «Наша команда» | 3 роли: ведущий эксперт, ИИ-архитектор, куратор; требования к роли; кандидаты с релевантным фактом | Приложение [4] | Карточка роли переворачивается и показывает кандидата |
| 8 | «Запросить детальный бюджет» | Форма: имя, компания, должность, e-mail, размер группы 20–25 | Детализированная экономика | Отправка письма на адрес Академии; ответ — детальный бюджет в PDF |

**Правила контента**

- Тексты сайта — короткие выдержки из артефактов, без новых цифр. Каждая цифра
  на сайте совпадает с цифрой в артефакте.
- Имя и фото кандидата публикуются после его письменного согласия; до согласия
  карточка показывает роль и требования.
- Цены, ставки и себестоимость на сайте не публикуются.
- Единственный инструмент на сайте — JustAI; модели называются «российские
  модели» и «модели в контуре компании».

## 3. Техническая реализация

| Компонент | Решение |
| --- | --- |
| Генератор | Jekyll: Markdown → HTML, сборка средствами GitHub Pages |
| Контент | `content/` — копии трёх публикуемых артефактов; `_data/timeline.yml` — 12 недель; `_data/team.yml` — роли и кандидаты; `_data/metrics.yml` — счётчики и факты |
| Шаблоны | `_layouts/default.html`, `_includes/` — по одному файлу на раздел сайта |
| Интерактив | `assets/js/timeline.js`, `assets/js/zones.js` — без внешних библиотек |
| Стили | `assets/css/site.css`; адаптивная вёрстка от 360 px; контраст текста по WCAG AA |
| Форма бюджета | `mailto:` на адрес Академии с заполненной темой и телом письма; внешних сервисов форм нет |
| Хостинг | GitHub Pages, источник публикации — GitHub Actions |

## 4. GitHub Actions

**Файл:** `.github/workflows/pages.yml`.

| Параметр | Значение |
| --- | --- |
| Триггеры | `push` в ветку `main`; ручной запуск `workflow_dispatch` |
| Права | `contents: read`, `pages: write`, `id-token: write` |
| Параллельность | Группа `pages`: одновременно идёт одна публикация |
| Сборка | Checkout → настройка Pages → Jekyll-сборка Markdown в HTML → загрузка `_site` как артефакта Pages |
| Деплой | Публикация артефакта в окружение `github-pages`; адрес сайта выводится в итоге запуска |
| Настройка репозитория | Settings → Pages → Source: GitHub Actions |

```yaml
name: Сайт-презентация

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v7
      - name: Настройка Pages
        uses: actions/configure-pages@v6
      - name: Сборка Jekyll
        uses: actions/jekyll-build-pages@v1
        with:
          source: ./
          destination: ./_site
      - name: Загрузка артефакта
        uses: actions/upload-pages-artifact@v5

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Публикация на GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v5
```

## 5. Промпт для инициализации

Промпт передаётся ИИ-агенту в новом пустом репозитории вместе с файлами
`01-project-summary.md`, `02-project-passport.md` и `03-appendix.md`.

```text
Ты — фронтенд-разработчик. Собери публичный одностраничный сайт-презентацию
программы «ИИ в работе с командой» на Jekyll и опубликуй его на GitHub Pages.

Исходные данные: файлы 01-project-summary.md, 02-project-passport.md,
03-appendix.md в корне репозитория. Перенеси их в content/. Новых цифр и
фактов не добавляй: каждая цифра на сайте берётся из этих файлов.

Разделы страницы по порядку:
1. Лендинг-хук: заголовок из 01, бизнес-цель, 4 счётчика (91 а.ч., 3 очных
   блока, 80% практики, 80% участников с прототипом), кнопка «Запросить
   детальный бюджет».
2. «Что получает руководитель»: 4 карточки из раздела 01.
3. «Светофор данных»: таблица зон из 02, уровень 2; переключатель зоны.
4. Интерактивный таймлайн недель 0–11 из таблицы 02, уровень 3: клик по
   неделе показывает темы, формат, а.ч., ведущего и результат; фильтр
   «очно / онлайн»; очные недели 1, 6, 11 выделены.
5. «Почему это работает»: факты из 03, раздел [1] и [3], со ссылками.
6. «Как мы измеряем результат»: L1–L4 из 02, уровень 5.
7. «Наша команда»: роли из 01 и кандидаты из 03, раздел [4]. Для кандидатов
   добавь в _data/team.yml поле consent: false; при false показывай только
   роль и требования.
8. «Запросить детальный бюджет»: форма с полями имя, компания, должность,
   e-mail, размер группы (20–25); отправка через mailto: на адрес из
   _config.yml (поле budget_email).

Техника:
- Jekyll без внешних тем; _data/timeline.yml, _data/team.yml, _data/metrics.yml;
  _layouts/default.html; _includes/ по одному файлу на раздел.
- JavaScript без внешних библиотек: assets/js/timeline.js, assets/js/zones.js.
- Адаптивная вёрстка от 360 px, контраст WCAG AA, alt у изображений.
- Workflow .github/workflows/pages.yml: push в main и workflow_dispatch;
  права contents: read, pages: write, id-token: write; concurrency group
  pages; job build: actions/checkout, actions/configure-pages,
  actions/jekyll-build-pages (source ./, destination ./_site),
  actions/upload-pages-artifact; job deploy: actions/deploy-pages в окружение
  github-pages.

Ограничения контента:
- Единственная платформа — JustAI. Другие ИИ-сервисы и вендоров моделей не
  называй; пиши «российские модели» и «модели в контуре компании».
- Цены, ставки и себестоимость не публикуй.
- Группа — строго 20–25 человек, сеты по 4–5 человек.

Проверка перед завершением:
- job build в workflow завершается без ошибок Jekyll;
- в таймлайне 12 недель, сумма а.ч. равна 91;
- все ссылки раздела «Почему это работает» открываются;
- workflow завершился успешно, сайт открывается по адресу GitHub Pages.
В README.md опиши, как обновить контент: заменить файлы в content/ и данные
в _data/, затем push в main.
```

## 6. Критерии приёмки RFC

| № | Критерий | Проверка |
| --- | --- | --- |
| 1 | Структура сайта из 8 разделов; разделы не повторяют файлы репозитория | Раздел 2 этого RFC |
| 2 | Каждый раздел сайта связан с артефактом-источником | Колонка «Источник» в разделе 2 |
| 3 | Таймлайн показывает 12 недель и 91 а.ч. | Проверка из промпта, раздел 5 |
| 4 | Workflow запускается на push в main и публикует сайт на GitHub Pages | Успешный запуск workflow, сайт открывается |
| 5 | Сборка Markdown → HTML выполняется Jekyll | Шаг `actions/jekyll-build-pages` в workflow |
| 6 | Промпт разворачивает сайт в пустом репозитории без доработки | Прогон промпта в тестовом репозитории |
| 7 | Цены, ставки и неподтверждённые имена на сайте отсутствуют | Ревью страницы перед публикацией |
| 8 | Кнопка «Запросить детальный бюджет» есть в первом и последнем экране | Ревью страницы |
