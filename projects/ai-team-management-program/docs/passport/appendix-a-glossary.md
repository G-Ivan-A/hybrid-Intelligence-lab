# Приложение А. Глоссарий

Приложение к [паспорту проекта](project-passport.md). Термины даны в том
значении, в котором они используются в паспорте, а не в общем.

| Термин | Значение в паспорте |
| --- | --- |
| Академический час (ак. ч) | 45 минут учебного времени (приказ Минобрнауки России № 266 от 24.03.2025). Очный день — 8 ак. ч, или 6 астрономических часов. |
| Артефакт A | Итерация 1; с версии 0.2 — кейс К5. Сводный дашборд задач подразделения на учебных данных: доля задач в срок, просрочки, концентрация задач на исполнителях, резерв ёмкости. |
| Артефакт B | Итерация 1; с версии 0.2 — кейс К3. Контур поручений: извлечение поручений, ответственных и сроков из протоколов и переписки, реестр поручений с контролем исполнения. |
| Асинхронный канал | Письменный канал связи с экспертом и куратором между модулями с ответом в течение рабочего дня. |
| Блум, таксономия | Иерархия учебных целей (пересмотренная версия Anderson & Krathwohl, 2001): помнить, понимать, применять, анализировать, оценивать, создавать. |
| Готовые ИИ-решения | ИИ-сервисы и агенты, которыми можно пользоваться без разработки моделей и интеграций: LLM-ассистенты, распознавание речи, BI-инструменты, агентные платформы. |
| Граничный случай (ГК) | Ситуация на краю допущений постановки, для которой архитектура имеет заранее заданный ответ. Список — в [постановке](../task-contract.md). |
| Вариант 1, вариант 2 бюджета | Вариант 1 — полный: разработка и поток раздельно, команда с опытом программ для топ-уровня. Вариант 2 — цена заказа до 3 млн ₽ без НДС за разработку и один поток при марже не ниже 25% и вкладе академии натурой. Расчёт — в [economics.md](economics.md). |
| Демо-день | Второй день модуля М4: участник показывает артефакт и два рутинных ИИ-сценария по рубрике. |
| Дашборд | См. «Артефакт A» и кейс К5. |
| Доступность контакта (Д0–Д3) | Внутренняя шкала пула кандидатов: Д3 — личный публичный профессиональный канал, через который можно написать напрямую; Д2 — публичная профессиональная страница без прямого сообщения; Д1 — только канал компании; Д0 — ничего не найдено. В аудите каналов и в отчёте об ИИ-агентах та же шкала обозначена К0–К3; в пуле буква «Д», чтобы не путать с кейсами К1–К5. Рейтинг кандидата — сумма соответствия роли (Р0–Р3) и доступности контакта. |
| Допущение (Д) | Принятое при постановке условие, при изменении которого архитектура пересматривается. |
| Delivery | Затраты на проведение одного потока. Повторяются в каждом потоке. |
| DoD (критерии готовности) | Проверяемые условия, при которых программа считается выполнившей задачу. Ключевое: не менее 80% участников продемонстрировали артефакт и два сценария. |
| Карта внедрения | Документ сета по единому шаблону: процесс → технология → сервисы → данные и ИБ → шаги пилота → метрики → риски. Группа получает по одной карте на кейс; сравнение карт — результат обучения РО-11. |
| Кейс (К1–К5) | Один из пяти управленческих процессов из запроса заказчика, на котором сет осваивает свою ИИ-технологию: К1 Встречи, К2 Календарь и коммуникации, К3 Поручения и сроки, К4 Перформанс команды, К5 Дашборд и сводная аналитика. Один сет — один кейс; правило активации — в [архитектуре](architecture.md#пять-кейсов-и-правило-активации). |
| КР-1…КР-5 | Критерии рубрики демо-дня (до версии 0.2 обозначались К-1…К-5). |
| Киркпатрик, модель | Четыре уровня оценки обучения: реакция, научение, поведение, результаты. Версия New World Kirkpatrick проектирует оценку от уровня 4. |
| Куратор | Роль, отвечающая за межмодульный период: диагностика, асинхронный канал, проверка маскирования, журнал применения, доходимость. |
| LTEM | Learning-Transfer Evaluation Model (Thalheimer): восемь ярусов оценки — от присутствия до влияния на результаты. Отделяет знание от выполнения задачи и от переноса. |
| Маржа | (Цена − Себестоимость) / Цена × 100%. Считается без НДС, отдельно для NRE и Delivery. |
| Маскирование | Замена персональных и конфиденциальных данных в тексте на условные метки до передачи текста в ИИ-сервис. |
| Межмодульный период | Около четырёх недель между очными модулями: применение на учебных данных, две групповые онлайн-сессии, сеты, обратная связь эксперта. Нагрузка — до 4 часов в неделю. |
| Метод успешных случаев | Метод оценки Бринкерхоффа: интервью с самыми и наименее успешными участниками, чтобы понять, что сработало и что помешало. |
| Модуль | Очный блок из двух дней подряд (М1–М4) или онлайн-блок (М0). |
| NRE | Non-Recurring Engineering: разовые затраты на разработку программы и учебного контура. Остаются у академии как актив. |
| Перенос | Применение изученного в реальной работе. Третий уровень Киркпатрика. |
| Полнота и точность | Метрики качества извлечения поручений. Полнота — доля найденных поручений от всех поручений в тексте. Точность — доля настоящих поручений среди найденных. |
| Резерв ёмкости | Разница между доступным временем команды и временем, занятым текущими задачами. Метрика дашборда, а не оценка сотрудников. |
| Рутинный ИИ-сценарий | Повторяющаяся задача руководителя, выполняемая с ИИ: подготовка к встрече, протокол, рассылка итогов, разбор календаря, черновики ответов. |
| Сет | Малая группа из 4–5 участников для межмодульной работы по модели Action Learning. С версии 0.2 каждый сет ведёт один кейс К1–К5 и выпускает карту внедрения. |
| Спейсинг | Распределение обучения во времени с интервалами вместо одного длинного блока. |
| Спонсор | Представитель топ-менеджмента заказчика, который открывает программу, согласует время участников и принимает решение о треке внедрения. |
| Учебный набор | Синтетические или обезличенные данные подразделения участника: задачи, исполнители, сроки, статусы, протоколы, переписка. Выдаётся до первого межмодульного периода. |
| Учебная песочница | Изолированная среда с разрешёнными сервисами и синтетическими данными для практики, когда политика ИБ не допускает внешние модели в корпоративной сети. |
| ФТ, НФТ | Функциональные и нефункциональные требования [постановки](../task-contract.md). |
| GRA, маркеры | Разметка надёжности утверждения: `●` подтверждено первоисточником, `◐` частично подтверждено или вторичный источник, `○` гипотеза или ориентир. |
| ИБ | Информационная безопасность заказчика. |
| ПДн | Персональные данные в смысле 152-ФЗ. |
