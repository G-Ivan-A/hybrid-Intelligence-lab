## Контекст и полная постановка

**User Story.** Как владелец, я хочу вынести программу, стратегию и исследования,
используемые для решений о доходе, в `G-Ivan-A/aether-orbis-proxeneta`, чтобы
вести закрытую работу независимо от публичного Хаба, сохранив историю,
доказательства, проверки и незавершённые задачи.

**Цель.** Наполненная спица с подтверждённым импортом и PRIVATE; после проверки
назначения — очищенный Хаб с совместимыми указателями. Режим — Creative из
#742; task type — миграция существующего проекта, не запуск продаж или пилота.

**SSOT.** Решения имени и закрытой границы — #742 (комментариев и обязательных
подзадач на 2026-11-17 нет). Метод —
[контракт E1–E6](../../../../ops/hub-project-extraction-contract.md),
[план #740 §4](../../../../projects/ai-team-management-program/strategy/new-repository-plan.md#4-шаги-создания-и-выноса),
предшествующий [PR #739](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/pull/739).
Метод опирается на [родительский анализ выноса #717](../../../../docs/analysis/2026-11-03-ba-meta-model-extraction-step1.md):
эта репетиция проверяет его контракт на другом проекте с закрытой границей.
Вход — merge PR #741, `546ebabb13a4679c6801d0eb5f344c6c3f6db177`.
Это исходная ревизия `origin/main` на старте #742, а не произвольное обновление
старого закрепления. Новый SHA при дрейфе требует решения владельца.

**Контракты задачи.** Байты и ссылки переносит инструмент из закреплённого
коммита. Исходные авторство и лицензия сохраняются; геном не копирует весь Хаб.
Содержательные исходники до E6 заморожены. Работа идёт через PR #743, без
мержа и переписывания истории. Подготовка объединена в один пакет по прямому
требованию task author, хотя типовой контракт предлагает отдельный PR на этап.

**Готово, когда.** Удалённые байты, история, ссылки, пять шагов CI, бэклог,
приватность и очистка подтверждены отдельно. Локальная репетиция и зелёный CI
Хаба не подменяют эти постусловия.

## Граница переноса и альтернативы

`manifest.tsv` содержит **79 файлов**, оба каталога целиком:
`projects/ai-team-management-program/` и `research/ai-team-management-program/`.
Включены стратегия, рынки RU/US/CN, позиционирование, кандидаты, экономика,
модели, PDF, изображения, исходники и журналы экспериментов, реестр источников
и RRP-модуль. Нет исключённых файлов внутри этих двух деревьев.

Вариант B из #740 (оставить исследования публичными как подтверждение
экспертизы) отвергнут: #742 прямо включает исследования для стратегии в
коммерческую границу. Вариант «только strategy/» оставляет рынки, модели и
данные решений в Хабе и не закрывает цель. Более широкий перенос всех
исследований Хаба тоже отвергнут: #742 разрешает общие исследования.

Отчёты о методологии обучения могли бы быть общими по теме, но в этом пакете
содержат выводы для выбора программы и связаны с проектными паспортами и
экономикой. Поэтому переносятся целиком, без публикации нового пересказа.
Общие исследования Хаба вне двух деревьев остаются в Хабе. Выделение из
смешанных документов нового общего материала — отдельное решение публикации;
для завершения этого переноса оно не требуется.

Пути в спице сохраняются. Это оставляет глубину `parents[4]` в двух Python
валидаторах и все внутренние ссылки работоспособными; уплощение в `strategy/`
и `research/exp-740/` добавило бы ненужную адаптацию исполнимого кода.

## Воспроизведение и доставка

Требуются git, Python 3.9+, bash, rg и git-filter-repo 2.47.0. Создание venv
не требует sudo. Команды выполняются последовательно; полная сборка продукта
и внешние сервисы не требуются.

```bash
python3 -m venv /tmp/proxeneta-venv
/tmp/proxeneta-venv/bin/pip install git-filter-repo==2.47.0
git clone https://github.com/G-Ivan-A/aether-orbis-proxeneta.git /tmp/proxeneta-base
python3 -I research/hub/exp/proxeneta-extraction-742/prepare-import.py \
  --target-base /tmp/proxeneta-base --out /tmp/proxeneta-import \
  --filter-repo /tmp/proxeneta-venv/bin/git-filter-repo
GFR=/tmp/proxeneta-venv/bin/git-filter-repo \
  bash research/hub/exp/proxeneta-extraction-742/test-preparation.sh
```

Результат: `/tmp/proxeneta-import/target` — git-репозиторий на ветке
`issue-742-ecf948625d8a`, с исходным коммитом спицы, геномом, импортированной
историей, журналом E1–E6, ADR импорта, лицензией, README, CI и бэклогом.
`proxeneta.bundle` рядом позволяет передать эту историю без повторного
исследования. Пакет локальный, не копия закрытых материалов в новый публичный
каталог Хаба. В git Хаба хранятся параметры и доказательства, не bundle.

Скрипт не пушит, не мержит, не меняет видимость, не удаляет источники. Он
отказывает при новых файлах или изменении README-заглушки цели, существующем выходе или выходе внутри
Хаба. Перед публикацией нужно заново проверить состояние и видимость спицы,
дать исполнителю write, создать PR из указанной ветки и проверить CI на SHA
импорта. Принимать с сохранением merge-истории, не squash. Если цель уже
изменилась, скрипт останавливается вместо перезаписи чужой работы.

## Порядок очистки после remote E6

Удалённая E6 должна подтвердить те же 79 файлов и историю, CI и 28 ID. Только
тогда в **этом PR** можно удалить содержимое обоих деревьев, оставив по одному
README-надгробию с полным соответствием старого пути новому; добавить две
записи `path_migrations`, архивный тег и проверить `path-migration-manifest.py`.
Стратегические подробности в надгробиях не повторяются.

Одновременно снимаются заморозка и пять проектных шагов CI Хаба, сохраняются
их копии в CI спицы; обновляются `projects/README.md`, `research/README.md`,
`ops/artifact-map.md`, структура/frontmatter allowlists и ссылки из активного
бэклога. Спринты 32/33 заменяются указателем после подтверждённого переноса;
ID не перенумеровываются. Исторические PR/CHANGELOG не выдаются за очищенную
историю. Общие валидаторы и чужие проекты не удаляются. Отдельную задачу
вместо незакрытого #742 для этих требований не создаём.

## Гипотезы, границы и внешний контроль

**H1:** безопасный перенос можно полностью завершить текущим доступом.
Контроль — права API и импортный манифест. Порог опровержения: хотя бы одно
неподтверждённое требование удалённой приёмки. Пять независимых проверок:

| Сценарий | Перспектива | Evidence | Вердикт |
| --- | --- | --- | --- |
| Нет записи в назначение | operational | `remote-state.json`: push=false | ❌ вскрывает границу; B-310, P2 |
| PUBLIC не защищает новые коммерческие данные | security | private=false, admin=false; GitHub Docs ext-449 | ❌ вскрывает границу; B-309, P2 |
| Тихая перезапись новой работы владельца | human governance | интеграционный тест отказывает dirty, новым файлам и изменённому README в README-only дереве | ✅ держит |
| Потеря байтов, режимов, истории или задач | architecture | 79/79, 63 коммита, 28 ID, пять проверок CI | ✅ держит локально |
| Старые копии останутся публичными | security/publication | GitHub Docs ext-450, #740 уже в main | ❌ вскрывает границу; вопрос Q-1 в PR #743 |

Итог: 2 ✅ / 0 ⚠️ / 3 ❌. H1 опровергнута доступом и границей приватности;
это не дефект байтового импорта. Маршрут — существующие B-309/B-310 и вопросы
PR #743, без дублирующих задач. Дополнительный тест отказывает существующему
выходу и записи внутрь Хаба; CI автоматически повторяет полный offline импорт.

**Альтернатива:** считать зелёный CI Хаба завершением. Отвергнута: он проверяет
локальную копию и не подтверждает доставку в назначение. Скрипт поэтому явно
пишет `NOT VERIFIED` в удалённые постусловия.

**Стратегический риск:** вынос из активного дерева и последующий PRIVATE не
делают опубликованные версии тайной. GitHub указывает, что публичные форки
остаются публичными, а удалённые данные могут остаться в клонах, PR и кэшах.
Переписывание истории не выполняется и не обещает полной секретности.
Рекомендация — обеспечить PRIVATE до новых закрытых данных; для старых версий
владелец выбирает принятие остаточной публичности или отдельную процедуру
санации истории с оценкой последствий. Обе ссылки зарегистрированы как
ext-449/450 в общем реестре внешних источников, автор GitHub, язык en,
дата изучения 2026-11-17. Вопросы Q-1/Q-2 вынесены в тело PR.
