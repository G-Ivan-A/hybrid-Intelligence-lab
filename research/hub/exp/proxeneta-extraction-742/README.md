## Контекст и полная постановка

**User Story.** Как владелец, я хочу вынести программу, стратегию и исследования,
используемые для решений о доходе, в `G-Ivan-A/aether-orbis-proxeneta`, чтобы
вести закрытую работу независимо от публичного Хаба, сохранив историю,
доказательства, проверки и незавершённые задачи.

**Цель.** Наполненная спица с подтверждённым импортом и PRIVATE; после проверки
назначения — очищенный Хаб с совместимыми указателями. Режим — Creative из
#742; task type — миграция существующего проекта. Продуктовые задачи стратегии
не становятся обязательными подзадачами миграции.

**SSOT.** Имя, коммерческая граница и последующий PRIVATE заданы в
[#742](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/issues/742).
Метод — [контракт E1–E6](../../../../ops/hub-project-extraction-contract.md),
[исходный план §4](https://github.com/G-Ivan-A/aether-orbis-proxeneta/blob/582f8a074e1377405429196764b562fa8cb32fb4/projects/ai-team-management-program/strategy/new-repository-plan.md#4-шаги-создания-и-выноса),
[родительский анализ #717](../../../../docs/analysis/2026-11-03-ba-meta-model-extraction-step1.md).
Вход — merge PR #741, `546ebabb13a4679c6801d0eb5f344c6c3f6db177`.
Он остаётся закреплённым источником, независимо от движения main.

**Уточнение владельца.** В [комментарии PR #743](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/pull/743#issuecomment-6940949086)

## Граница и проверенные альтернативы

[Манифест](manifest.tsv) включает оба дерева **целиком**, без исключений:
`projects/ai-team-management-program/` и `research/ai-team-management-program/`.
Коммерческая граница включает стратегию, исследования, данные решений,
воспроизводимые модели и проектные результаты, а не только персональные данные.

Вариант B плана #740 — оставить исследования публичными — отвергнут прямым
решением #742. Перенос одного `strategy/` оставил бы доказательства и данные
решений в Хабе. Перенос всех исследований Хаба тоже не нужен: общие материалы
вне этих деревьев разрешены и не затрагиваются. Смешанные проектные документы
перенесены полностью; новый публичный пересказ коммерческих выводов не создаётся.

Пути сохраняются: это удерживает глубину `parents[4]` двух валидаторов и
внутренние ссылки. Уплощение каталогов добавляло бы адаптацию без пользы для цели.

## Воспроизведение и границы очистки

`prepare-import.py` и `test-preparation.sh` — сохранённая репетиция подготовки,
а не повторный импорт поверх уже наполненной спицы. Для её воспроизведения
используются checkout Хаба **до очистки**
`0d80d42c615c14798373ce980465d3ed82e33934`, исходная цель
`e59e3f826cb35db47d9b17e7e15b8000456454df` и git-filter-repo 2.47.0.
Команда с текущим очищенным деревом или новой целью должна отказать, а не
ослабить защиту. Локальные результаты сохранены в `local-verification.json`
и `test-preparation.log`; они не выдаются за удалённые результаты.

Историческая команда (в отдельном checkout указанной ревизии Хаба):

```bash
python3 -I research/hub/exp/proxeneta-extraction-742/prepare-import.py \
  --target-base /tmp/proxeneta-original-base --out /tmp/proxeneta-import \
  --filter-repo /tmp/proxeneta-venv/bin/git-filter-repo
GFR=/tmp/proxeneta-venv/bin/git-filter-repo \
  bash research/hub/exp/proxeneta-extraction-742/test-preparation.sh
```

Текущая очистка проверяется `path-migration-manifest.py check`, валидаторами
структуры и ссылок, тестами redirect и архивных тегов. Общие валидаторы и
чужие проекты сохранены. Пять проектных шагов CI исполняются в спице; offline
импорт и заморозка #742 завершили свою роль в CI Хаба. Заморозка проекта БА
остаётся активна.

Оба надгробия адресуют каждый прежний файл на проверенный полный SHA спицы.
Исходные README тоже сохранены в спице. Два разных архивных тега объявлены на
общем коммите `546ebabb13a4`. Первая попытка CI создала
`archive/proxeneta-project-2026-11`; после отказа GitHub (`Internal Server Error`)
повторная попытка создала `archive/proxeneta-research-2026-11`. `git ls-remote`
и `tools/archive-tags.py plan` подтвердили оба аннотированных тега на этом SHA.
Проверка защиты на `main` остаётся красной: API возвращает HTTP 403, поскольку
текущий тариф GitHub не поддерживает rulesets для приватного Хаба. [Повторный запуск CI](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/actions/runs/44169153166/attempts/2), [требования GitHub](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets).

## Гипотезы и границы: результат Creative-проверки

**H1:** текущих прав достаточно для полного завершения. Порог опровержения —
хотя бы одно невыполненное требование приёмки.

| Сценарий | Перспектива | Evidence и результат |
| --- | --- | --- |
| Нет записи в назначение | operational | Первичная граница снята: принято приглашение write, импорт опубликован |
| PUBLIC не защищает новый коммерческий слой | security | изначально `private=false`; после действия владельца GitHub API вернул `private=true` |
| Перезапись новой работы владельца | human governance | Тесты отказывают dirty, новым файлам, изменённому README и существующему выходу |
| Потеря байтов, режимов, истории, задач или CI | architecture | Независимый remote E6 и CI подтверждают все 79/63/28 и пять шагов |
| Старые копии останутся публичными | publication | ext-450 и опубликованная история Хаба; вопрос Q-1 в PR #743 остаётся |

H1 по-прежнему опровергнута: write не даёт admin и права принять собственный PR.
Альтернатива «зелёный CI Хаба означает завершение» отвергнута: CI назначения,
приёмка человека, PRIVATE и защищённый архив проверяются отдельно.

**Стратегический риск.** Очистка активного дерева и последующий PRIVATE не
делают опубликованные версии тайной. GitHub описывает сохранение публичных
форков и копий в клонах, PR и кэшах (GitHub Docs ext-449/450 в общем реестре,
дата изучения 2026-11-17). Рекомендация — PRIVATE до новых закрытых данных;
для старой истории владелец выбирает принятие остаточной публичности или
отдельную санацию с оценкой последствий. История здесь не переписывается.
Этот выбор и конкретные действия владельца вынесены в тело PR #743.
