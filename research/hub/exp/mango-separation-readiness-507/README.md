# exp: mango-separation-readiness-507

Evidence container for the analysis report
[`../../../../docs/analysis/2026-08-13-mango-separation-and-runs-readiness.md`](../../../../docs/analysis/2026-08-13-mango-separation-and-runs-readiness.md),
issue [#507](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/issues/507).

## Что здесь проверяется

Постановка #507 требует оценить готовность `mango_ba_prompts` к разделению
репозиториев (ADR-009) и к серии из 20+ BA-прогонов. Оба вопроса нельзя закрыть
чтением документов: план миграции B-080 снят со снимка `295b65d` от 2026-07-17, и
до начала работы нужно проверить измерением, **не разошлась ли реальность с
планом** — изменилась ли спица, изменился ли Хаб, выполняются ли контракты
прогонов и промптов на существующих артефактах.

Контейнер отвечает только на **измеримую** часть вопроса: числа, наличие
каталогов, соблюдение полей, битые ссылки, объём дрейфа. Приоритизация,
критический путь и рекомендации — в родительском Analysis.

## Метод

`scan-mango-readiness.sh` работает по локальному клону спицы и локальному дереву
Хаба, только на чтение, и снимает шесть групп измерений:

1. **Снимок** — HEAD и дата обоих репозиториев, чтобы числа отчёта были
   привязаны к конкретным коммитам, а не к «сегодня».
2. **Инвентаризация** — число файлов и число файлов с упоминанием бренда по
   каталогам верхнего уровня (`git grep -lie mango`). Это прямой вход в
   классификацию R1–R8 плана миграции B-080.
3. **Контракт прогонов** — для каждого `runs/*/*/metadata.yaml` проверяются семь
   обязательных полей `runs-contract-standard.md` и наполнение `feedback/` и
   `logs/`. Каталог, содержащий только `.gitkeep`, считается пустым: наличие
   каталога не является наличием данных.
4. **Контракт промптов** — `prompt-standard.md` спицы требует ровно шесть полей
   frontmatter; скрипт перечисляет файлы с полями сверх этого набора.
5. **Битые относительные ссылки** — все markdown-ссылки, чья цель не существует
   на диске. Ссылки-плейсхолдеры (`<path>`, `...`) считаются отдельно и дефектом
   не являются: это синтаксис примеров в стандартах.
6. **Дрейф Хаба** — число коммитов Хаба с `last_sync.hub_sha` из
   `.hub-profile.json` и список новых каталогов методологии; далее наличие
   целевых каталогов ADR-009 в спице и наполнение модулей `research/ai-education`
   прикладными артефактами.

Классификация намеренно формальная: скрипт нигде не решает, «правильна» ли
ссылка или «нужен» ли артефакт, — он только фиксирует наблюдаемое состояние.

### Ограничения измерения

- Признак бренда — регистронезависимая подстрока `mango` в тексте файла. Это
  верхняя граница по упоминаниям и нижняя по приватности: клиентские данные без
  слова «Mango» такой поиск не находит, поэтому число **не заменяет**
  анонимизационный шлюз A8 плана B-080.
- Битые ссылки считаются только по относительным путям на диске; внешние URL и
  якоря внутри файлов не проверяются.
- Frontmatter промптов разбирается плоско — по ключам верхнего уровня.
- Дрейф Хаба измеряется числом коммитов и списком новых каталогов, а не
  содержательным дифом: объём изменений не равен объёму работы по синхронизации.
- Снимок спицы взят с ветки по умолчанию на `295b65d`; при последующих изменениях
  репозиториев числа изменятся — это ожидаемо, оба SHA печатаются в шапке лога.

## Результаты

Снимок: mango `295b65d` (2026-07-14), Хаб `f10c927` (2026-08-13). Полный вывод —
[`scan-2026-08-13.log`](scan-2026-08-13.log).

| Показатель | Значение |
| --- | --- |
| Файлов в спице / из них с упоминанием бренда | 5 346 / 1 337 |
| Крупнейший каталог | `kb/` — 5 077 файлов, 1 156 с брендом |
| Прогонов с полным набором обязательных полей | 12 / 12 |
| Прогонов с записанной моделью | 2 / 12 (`RUN-0010`, `RUN-0012`) |
| Прогонов с непустым `feedback/` | 0 / 12 |
| Прогонов с непустым `logs/` | 2 / 12 (`RUN-0011`, `RUN-0012`) |
| Промптов с полями сверх шести обязательных | 8 / 33 (2 README, 6 в `archive/`) |
| Битых относительных ссылок / из них в `standards/GLOSSARY.md` | 57 / 20 |
| Коммитов Хаба с последней синхронизации (`b683341`, 2026-06-13) | 610 |
| Новых каталогов методологии в Хабе | `ai-rules/` (4 файла), `ai-governance/` (3) |
| Каталоги ADR-009, отсутствующие в спице | `evals/`, `internal-rfc/`, `internal-docs/` |
| Модулей `research/ai-education` с прикладным артефактом | 1 / 8 (`evaluation`) |

Основных результатов три. Первый: спица не менялась с даты снимка B-080 —
маршрутная таблица плана миграции остаётся валидной без пересчёта. Второй:
разошёлся **Хаб**, а не спица (610 коммитов, два новых корпуса методологии,
которых на момент последней синхронизации не существовало). Третий:
воспроизводимость прогонов не обеспечена не структурой, а наполнением — форма
соблюдена в 12 случаях из 12, при этом модель не записана в 10 и обратная связь
не собрана ни в одном.

## Воспроизведение

```bash
git clone https://github.com/G-Ivan-A/mango_ba_prompts /tmp/mango-clone
research/hub/exp/mango-separation-readiness-507/scan-mango-readiness.sh /tmp/mango-clone
```

Сети требует только клонирование спицы; сам скрипт работает офлайн по двум
локальным деревьям. Числа отчёта воспроизводятся на mango `295b65d` и Хабе
`f10c927`.
