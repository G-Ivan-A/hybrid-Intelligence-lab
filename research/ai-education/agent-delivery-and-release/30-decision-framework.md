# Рамка решений: как выпускать, чем измерять, когда откатывать

Правило файла: **каждое решение сформулировано как условие с наблюдаемым
порогом**. Числа, взятые из источника, помечены ссылкой; числа, введённые здесь
без источника, помечены как «инженерный дефолт Хаба, подлежит замеру» — они не
являются нормой и не создают правил Хаба (AI Governance, Rule 4).

## 1. Что считается релизом (триггеры)

Релизом считается изменение любой единицы U1–U7 ([`20-taxonomy.md`](20-taxonomy.md)),
в том числе не инициированное командой.

| Событие | Релиз? | Почему |
| --- | --- | --- |
| Правка формулировки в системном промпте | **да** | CACE: изолированных изменений нет ([`10-theory.md §2`](10-theory.md)) |
| Смена идентификатора версии модели | **да** | другое поведение при том же коде |
| Провайдер объявил депрекацию используемой версии | **да, запланированный** | миграция обязательна к дате ([Anthropic](https://docs.claude.com/en/docs/about-claude/model-deprecations), [OpenAI](https://platform.openai.com/docs/deprecations)) |
| Переиндексация корпуса / смена эмбеддера | **да** | меняется содержимое контекста |
| Изменение схемы или описания инструмента | **да** | меняется частота и корректность вызовов |
| Изменение порога эскалации или guardrail'а | **да** | меняется распределение исходов |
| Правка комментария, README, форматирование | нет | не влияет на вход модели |

Стоп-правило: **если нельзя назвать зафиксированные версии всех U1–U7 — релиза
нет, есть неконтролируемое изменение прода.** Такое состояние возвращается к
воротам, а не оценивается.

## 2. Выбор стратегии выката

Решение принимается по трём наблюдаемым величинам: требование к времени
восстановления (MTTR), бюджет ресурсов, обратимость последствий (ось E).

| Условие | Решение | Основание |
| --- | --- | --- |
| **MTTR критичен: целевое время восстановления < 5 мин** | **blue-green (S2)** — возврат переключением трафика | обратимость одним действием ([Fowler](https://martinfowler.com/bliki/BlueGreenDeployment.html)); порог 5 мин — инженерный дефолт Хаба, подлежит замеру |
| MTTR не критичен, но эффект изменения виден только на реальном распределении | **canary (S4)** с автоанализом шагов | [SRE Workbook, Canarying Releases](https://sre.google/workbook/canarying-releases/), [Flagger](https://docs.flagger.app/) |
| **Бюджет ресурсов ограничен** (нет возможности держать двойной парк) | **rolling update (S3)** | S2 требует удвоения среды ([Fowler](https://martinfowler.com/bliki/BlueGreenDeployment.html)); механика — [Kubernetes](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/#rolling-update-deployment) |
| Изменение полностью покрыто офлайн-набором, класс риска низкий | **S1** (ворота + полная замена) | экспозиция не добавляет информации |
| Последствия ошибки необратимы (R5) либо действие дорого в ошибке | **shadow (S5)**, затем **S7** (расширение мандата) | нулевая экспозиция пользователей; человек в контуре для высокого риска ([OpenAI](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)) |
| Вопрос звучит как «стало ли лучше», а не «не сломалось ли» | **S6** (онлайн A/B) | требуется дизайн эксперимента и мощность выборки |

Комбинирование разрешено и типично: S2 как транспорт + C2 (флаг) как
переключатель мандата. Запрещённая комбинация одна: **стратегия с экспозицией
(S3, S4, S6) без заранее заведённого механизма отката R1 или R2**.

## 3. Ворота выпуска: из чего собираются

Ворота собираются из трёх слагаемых и **не изобретаются этим модулем**:

1. Пороги качества и правила прохождения — [`evaluation/30-decision-framework.md`](../evaluation/30-decision-framework.md)
   (критические инварианты, нижняя граница доверительного интервала, срезы).
2. Стоимость ошибки и требуемый ярус контроля — [`task-processing/30-decision-framework.md`](../task-processing/30-decision-framework.md)
   (G1–G7).
3. Готовность инфраструктуры релиза — проверки этого файла (§4–§6).

| Ворота | Условие прохождения | Условие блокировки |
| --- | --- | --- |
| **W1. Воспроизводимость** | зафиксированы версии всех U1–U7 | любая единица «текущая»/по алиасу |
| **W2. Качество** | пороги [`evaluation/`](../evaluation/00-introduction.md) выполнены на регрессионном наборе | нарушен критический инвариант или регрессировал критический срез |
| **W3. Обратимость** | доступный класс отката ≤ R3 либо снапшот для R4 создан | требуемый откат — R4 без снапшота или R5 |
| **W4. Наблюдаемость** | метрики выката пишутся и видны ([`observability/`](../observability/00-introduction.md)) | сравнение канарейки с baseline невозможно |
| **W5. Экспозиция** | стратегия и механизм назначены явно (§2) | «выкатим и посмотрим» |

Ворота — **конъюнкция**: невыполнение любого блокирует релиз. Компенсация
высокого W2 отсутствующим W3 не допускается — это и есть механизм, которым
хорошие метрики превращаются в длительный инцидент.

## 4. Отдельные ворота для изменения промпта и изменения модели

Эти два случая выделены потому, что они не проходят через сборку кода и потому
чаще всего выкатываются мимо релизного контура.

### 4.1. Изменение промпта (U2)

Владение объектом — [`agent-context-engineering/`](../agent-context-engineering/00-introduction.md);
здесь задаётся только выпуск.

| Условие | Решение |
| --- | --- |
| Правка не меняет поведение (опечатка, формат) — подтверждено прогоном набора | S1, обычные ворота |
| Правка меняет инструкции или порядок блоков | прогон регрессионного набора **до** выката; при отсутствии набора релиз не проходит W2 |
| Улучшение измерено, но разница меньше разброса от формы формулировки | **не выпускать как улучшение**; выпускать только с отметкой «нейтрально» ([Sclar et al.](https://arxiv.org/abs/2310.11324)) |
| Правка затрагивает поведение с побочными эффектами | S5 (shadow) перед экспозицией; C4 (kill switch) обязателен |

### 4.2. Изменение модели (U1)

| Условие | Решение |
| --- | --- |
| Смена версии инициирована провайдером (депрекация) | обрабатывается как полноценный релиз с полным прогоном набора; дата депрекации → срок в плане ([Anthropic](https://docs.claude.com/en/docs/about-claude/model-deprecations), [OpenAI](https://platform.openai.com/docs/deprecations)) |
| Используется плавающий алиас версии | **дефект конфигурации**: пин обязателен, иначе W1 не проходит |
| Смена семейства или крупной версии модели | промпт **перепроверяется**, а не переносится: рекомендации по размещению инструкций различаются между вендорами ([`agent-context-engineering/30-decision-framework.md §6`](../agent-context-engineering/30-decision-framework.md)) |
| Старая версия ещё доступна | R3 остаётся доступным откатом; после отключения провайдером — нет, и это меняет класс риска релиза |

## 5. Параметры canary для агента

Веб-практика задаёт шаги по доле трафика; для агента этого недостаточно —
решающим ограничением является **число завершённых прогонов**, а не доля
([`10-theory.md §5`](10-theory.md)).

| Параметр | Правило | Статус числа |
| --- | --- | --- |
| Шаг доли трафика | пошаговое расширение с анализом на каждом шаге; типичная схема платформ — 5 → 20 → 50 → 100% | схема шагов — [Flagger](https://docs.flagger.app/), [Argo Rollouts](https://argoproj.github.io/argo-rollouts/); конкретные значения настраиваются |
| **Минимальное число прогонов на шаге** | шаг не завершается, пока не набрано N завершённых прогонов, покрывающих ключевые срезы | **инженерный дефолт Хаба, подлежит замеру**: N выводится из требуемой мощности по правилам [`evaluation/`](../evaluation/00-introduction.md), а не назначается |
| Длительность шага | не меньше времени, за которое проходит полный суточный цикл типов нагрузки | [SRE Workbook](https://sre.google/workbook/canarying-releases/): канарейка должна увидеть репрезентативный трафик |
| Порог отказа шага | число неуспешных проверок подряд, после которого выкат останавливается и откатывается | механика — [Flagger](https://docs.flagger.app/) (`threshold`); значение — локально |
| Метрики сравнения | доля успеха, доля ошибок инструментов, латентность, стоимость прогона; сравнение с одновременно работающим baseline, а не с историей | [SRE Workbook](https://sre.google/workbook/canarying-releases/) |

Стоп-правило мощности: **если за отведённое время шага набрано меньше
минимального N, решение «продолжать» не принимается** — выкат либо ждёт, либо
возвращается; «данных мало, но выглядит нормально» является нарушением W2.

## 6. Правила отката: триггер → класс → бюджет времени

| Триггер (наблюдаемый) | Класс отката | Кто принимает решение | Целевой бюджет времени |
| --- | --- | --- | --- |
| Нарушен критический инвариант качества на канарейке | R1 (вернуть вес) | автоматика | секунды |
| Доля ошибок вызова инструментов выше порога baseline | R1 или R2 | автоматика | секунды |
| Рост стоимости или латентности прогона выше согласованного потолка | R1 | автоматика | секунды |
| Единичный тяжёлый инцидент с внешним эффектом | R2 (kill switch) | дежурный, без согласований | минуты |
| Деградация видна только на агрегате за сутки | R3 | человек, с разбором | часы |
| Испорчены данные: индекс или память | R4 (снапшот) | человек | часы; **без снапшота недоступно** |
| Совершено необратимое действие | R5 — отката нет | инцидент + компенсация | не применимо |

Правило, определяющее устройство контура, а не реакцию: **право на автоматический
откат выдаётся метрике только после того, как измерена её частота ложных
срабатываний**. Автооткат по неоткалиброванной метрике превращает шум в
недоступность.

Измеряемый результат всей секции — метрика **time to restore service** из
четвёрки DORA ([four keys](https://dora.dev/guides/dora-metrics-four-keys/));
вместе с ней отслеживаются частота выкатов, время изменения и доля неудачных
изменений. Целевые значения назначаются локально; DORA относит к верхнему
уровню восстановление сервиса менее чем за час.

## 7. Пороги дрейфа

| Сигнал | Порог | Статус числа | Действие при срабатывании |
| --- | --- | --- | --- |
| PSI между текущим и опорным распределением входов | ~0.1 — умеренный сдвиг, ~0.2 — существенный | пороги по умолчанию платформ мониторинга ([Evidently](https://docs.evidentlyai.com/metrics/explainer_drift)); требуют локальной калибровки | проверка, не откат: запуск замера качества |
| Jensen–Shannon дистанция | порог по умолчанию того же порядка | там же | то же |
| KS-тест для непрерывных признаков | p < 0.05 | стандартный уровень значимости; при множественных сравнениях требует поправки | то же |
| Доля ошибок вызова инструмента (D4) | превышение baseline сверх согласованного допуска | локально | контракт-тест инструмента, при необходимости R2 |
| Расхождение с зафиксированным набором на пине (D5) | любое статистически значимое расхождение | локально | обращаться с новой версией модели как с релизом |

Правило приоритета сигналов: **дрейф входа — вход в процедуру проверки, а не
основание для отката**. Основанием для отката является метрика качества или
ошибок, а не расстояние между распределениями ([`10-theory.md §7`](10-theory.md)).

## 8. Замыкание обратной связи

| Решение | Правило | Статус |
| --- | --- | --- |
| Какая доля прогонов уходит в ручной разбор (F4) | выбирается по стоимости разбора и требуемой точности оценки; выборка **стратифицирована** по срезам, а не случайна равномерно | схема выборки — [`evaluation/`](../evaluation/00-introduction.md) |
| Что обязано попасть в разбор независимо от выборки | все production escape'ы (F5) и все срабатывания отката | правило модуля |
| Что попадает в golden set | каждый подтверждённый escape становится кейсом набора до закрытия инцидента | [`10-theory.md §8`](10-theory.md), [ML Test Score](https://research.google/pubs/the-ml-test-score-a-rubric-for-ml-production-readiness-and-technical-debt-reduction/) |
| Кто решает о причине | разбор без поиска виновного, цель — устранение причины | [SRE, Postmortem Culture](https://sre.google/sre-book/postmortem-culture/) |
| Когда набор пересматривается целиком | при подтверждённом concept drift (D3): старые ожидаемые ответы становятся неверными | [`10-theory.md §7`](10-theory.md) |

Стоп-правило контура: **инцидент не считается закрытым, пока не существует
кейса, который бы его поймал.** Иначе следующая итерация повторит его на тех же
воротах.

## 9. Антипаттерны и их наблюдаемые триггеры

| Антипаттерн | Наблюдаемый триггер | Чем закрывается |
| --- | --- | --- |
| **Плавающая версия модели** | в конфигурации алиас без идентификатора версии | §4.2, ворота W1 |
| **Промпт мимо релиза** | правка системного промпта выкачена без прогона набора | §4.1 |
| **Canary как ритуал** | шаг завершён по таймеру при числе прогонов ниже минимального | §5, стоп-правило мощности |
| **Откат-обещание** | в плане релиза указан откат, но флага или снапшота не существует | W3, ось E |
| **Автооткат по шумной метрике** | доля ложных срабатываний отката не измерена | §6 |
| **Дрейф как приговор** | откат выполнен по превышению PSI без замера качества | §7 |
| **Инцидент без кейса** | escape закрыт правкой промпта, набор не изменился | §8 |
| **Необратимое действие в canary** | новая версия с побочными эффектами получила долю реального трафика без S5/S7 | §2, ярусы G4–G7 [`task-processing/`](../task-processing/30-decision-framework.md) |
| **Ворота из среднего балла** | релиз прошёл при регрессии критического среза | [`evaluation/30-decision-framework.md`](../evaluation/30-decision-framework.md) |

## Что рамка сознательно не решает

- **Значения порогов качества.** Их назначает [`evaluation/`](../evaluation/00-introduction.md);
  здесь они используются как вход ворот.
- **Внутреннюю трассировку прогона.** Как устроены спаны, атрибуты и ставки
  сэмплирования — [`observability/`](../observability/00-introduction.md).
- **Пайплайн сборки кода.** Раннеры, кэш, матрица окружений — [`research/cicd/`](../../cicd/README.md).
- **Содержание промпта.** Что писать в инструкции — [`agent-context-engineering/`](../agent-context-engineering/00-introduction.md);
  здесь — только условия его выпуска.
- **Организационные роли.** Кто дежурный и кто утверждает релиз — решение
  фаундера (AI Governance, Rule 4); модуль описывает выбор, а не назначает
  ответственных.
- **Числа Хаба.** Все значения, помеченные «инженерный дефолт Хаба», остаются
  гипотезами до локального замера ([`50-open-research.md`](50-open-research.md)).
