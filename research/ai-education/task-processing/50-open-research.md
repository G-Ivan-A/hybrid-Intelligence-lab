## 2. Что этот модуль сказал о Reference Research Pattern

Ответ на RQ23–RQ24 ([00-introduction.md](00-introduction.md)). Модуль —
**вторая** реализация паттерна и **первая** на домене, устроенном иначе, чем
Retrieval.

| Элемент паттерна | Как повёл себя на Task Processing |
| --- | --- |
| `00-introduction` | без изменений: карта чтения и граф зависимостей перенеслись напрямую |
| `10-theory` | без изменений по форме; сигнатура домена (`A = Policy(M, S, T, C)`) заполнилась естественно, как и `S = Decision(KB, Query, Constraints)` в Retrieval |
| `20-taxonomy` | **изменение**: в Retrieval таксономии были аргументами одной сигнатуры и сводились в одну матрицу. Здесь три оси **ортогональны** и в одну матрицу не сводятся: матрица в `30` соединяет две оси, а третья (ярус контроля) входит как выход, а не как координата |
| `30-decision-framework` | **изменение смысла**: в Retrieval рамка выбирает *одну стратегию* из перечня; здесь — *конфигурацию* из трёх независимых осей. Файл остался на месте, но перестал быть «выбором из списка» |
| `40-practice-and-cases` | без изменений по форме; разделение классов источников S1–S5 оказалось строго необходимым, потому что спецификации и отчёты вендоров смешаны плотнее, чем в Retrieval |
| `50-open-research` | без изменений |

**Вывод по паттерну (не решение).** Форма перенеслась; смысл файла
`30-decision-framework` — нет. Это ровно та граница, которую RFC назвал в
Critical Analysis («домен без пространства решений»), но проявившаяся в другой
форме: пространство решений здесь есть, оно многомерно. Возможная формулировка
для будущей ревизии паттерна: `30-decision-framework` — это файл *точек
решений и правил выбора*, а не обязательно *одной матрицы*. Принимать ли эту
правку — вопрос к фаундеру; настоящий модуль его только ставит.

**Что паттерн выдержал безусловно.** Механизм обратной связи «практика →
теория» (P5 RFC) сработал в реальном времени: расхождение постановки #457 с
инженерными наблюдениями (§«компактность мандата») было воспроизведено на двух
независимых источниках и **изменило рамку**, а не осталось примечанием
([40 §7](40-practice-and-cases.md)). Это первое зафиксированное срабатывание
механизма.

## 4. Связь модулей знаний

Ответ на RQ21–RQ22. Постановка #457 перечислила смежные модули: Tool Use /
Execution, Self-Reflection / Critique / Evaluation, Routing & Multi-Agent
Communication, Observability / Telemetry — и разрешила исправить перечень.
**Перечень исправлен: два элемента переклассифицированы, один добавлен.**

| Модуль | Отношение к Task Processing | Обоснование |
| --- | --- | --- |
| **Retrieval** | поставщик содержимого `E4 Fact index` и части `E5 State` | сосед: отвечает на другой вопрос («что считать контекстом»), см. [retrieval/00-introduction.md](../retrieval/00-introduction.md) |
| **Memory** | временная развёртка `E5` и хранилище `E12 Trace` | сосед; обратная связь: исполнение порождает записи, которые Memory вернёт как факт (H15, риск самоотравления — O7) |
| **Tool Use / Execution** | **не отдельный модуль, а `E8`/`E9` внутри Task Processing** | инструмент без задачи бессмыслен; выделение в отдельный домен разрывает связку «действие ↔ его санкционирование», которая и есть предмет данного модуля |
| **Self-Reflection / Critique** | **не отдельный модуль, а подход к планированию P7 и ярус контроля G6** | это два разных объекта, ошибочно объединённых одним словом: рефлексия как форма планирования (внутренняя) и критика как верификация (внешняя). Их слияние — источник H9 |
| **Evaluation** | **отдельный модуль**, отщепляемый от Self-Reflection | измеряет систему извне и вне цикла исполнения; имеет собственные объекты (рубрика, бенчмарк, метрика соблюдения политики) |
| **Routing & Multi-Agent Communication** | сосед; частично пересекается через `P4`/`P5` и контракт делегирования | самостоятелен: протокол сообщений и топология существуют независимо от конкретной задачи |
| **Observability / Telemetry** | сосед; поставляет `E12` и делает G7 исполнимым | самостоятелен и уже стандартизирован извне (OTel GenAI) |
| **Governance / Authorization** | **добавлен**: отсутствовал в исходном перечне | ярусы G5 и G7 требуют ответа на вопрос «кто вправе санкционировать», который не принадлежит ни Task Processing, ни Observability. Без него `E2 Constraint` не имеет владельца |

Схема:

```
   Retrieval ──► E4 Fact index ─┐
   Memory ─────► E5 State ──────┤
                                ▼
                       ┌──────────────────┐
   Governance/Authz ──►│  TASK PROCESSING │◄── Routing & MAS Communication
   (кто вправе)        │  E1..E12         │    (как передаётся мандат)
                       └───┬──────────┬───┘
                           │          │
                 E12 Trace │          │ результат
                           ▼          ▼
                  Observability     Evaluation
                           │          │
                           └────► Memory (обратная запись; риск O7)
```

**Как это продолжает линию Reference Pattern.** Retrieval отвечал «как найти и
отфильтровать контекст», Memory — «как хранить и извлекать состояние во
времени», Task Processing — «как из цели, контекста и ограничений получить
проверяемый результат». Три вопроса образуют цепочку: контекст → состояние →
действие. Паттерн проверяется именно на том, что при смене вопроса меняются
таксономии и матрица, но не порядок работы (постановка → теория → таксономия →
рамка решений → практика → открытые вопросы).

## 5. Глоссарий

| Термин | Значение в этом модуле |
| --- | --- |
| **Мандат** | постановка с полностью определёнными целью, границами и критерием приёмки и намеренно неопределённым способом достижения ([10 §1.3](10-theory.md)) |
| **Индекс фактов (Fact index, SSOT)** | множество источников, признанных истинными для данной задачи; `E4` |
| **Guardrail** | механизм, удерживающий ограничение; различается ярусом G1–G7 по тому, кто его исполняет |
| **Ярус контроля** | степень выноса правила из-под контроля модели ([20 §3](20-taxonomy.md)) |
| **HITL-гейт** | прерывание исполнения на классе действий с передачей решения человеку |
| **Tripwire** | признак срабатывания гардрейла, останавливающий исполнение исключением |
| **Pre-flight верификация** | сверка состояния среды и индекса фактов до первого содержательного действия ([30 §3](30-decision-framework.md)) |
| **Orchestrator / Worker** | разделение: оркестратор задаёт «что», воркер решает «как» |
| **Handoff** | передача задачи другому агенту, выраженная как вызов инструмента |
| **Обратимость действия** | возможность вернуть систему в предшествующее состояние; основной критерий выбора яруса |
| **Трасса (Trace)** | упорядоченная запись плана, шагов, действий и наблюдений; `E12` |
| **Уровень автономии A0–A5** | наблюдаемое распределение решений между человеком, агентом и средой ([30 §6](30-decision-framework.md)) |

## 7. Самоаудит

**Признанные слабости.**

1. **Выборка фреймворков — шесть.** Утверждение о «сходимости индустрии»
   ([40 §6](40-practice-and-cases.md)) опирается на LangGraph, OpenAI Agents
   SDK, CrewAI, AutoGen, MCP и OTel. Enterprise-платформы (managed-агенты
   облачных провайдеров, внутренние системы) не рассмотрены; там ярусы могут
   быть распределены иначе.
2. **Ни одно число не воспроизведено независимо.** ×4, ×15, 80%, +90.2% —
   один источник, собственные данные вендора. В рамку заложены только
   качественные следствия.
3. **Шкала мандатов M0–M5 одномерна**, а реальные постановки гибридны
   ([20 §1](20-taxonomy.md)). Это огрубление, а не свойство предметной области.
4. **Матрица [30 §1](30-decision-framework.md) не валидирована.** Она выведена
   из объектной модели и прецедентов, но не проверена ни на одном корпусе
   задач. Пороги «цены ошибки» (L/M/H) не операционализированы.
5. **Шкала автономии A0–A5 не измерена.** Отнесение системы к уровню
   выполняется экспертно по трассе; межэкспертное согласие не проверялось.
6. **Раздел о Хабе опирается на выборку размера два**, обе задачи —
   механические, оба прецедента — один исполнитель. Любое обобщение с них
   неправомерно, и это указано на месте ([40 §5](40-practice-and-cases.md)).
7. **Русскоязычная и азиатская индустриальная практика не рассмотрена.**
   Источники — англоязычные; смещение выборки не оценивалось.
8. **Отсутствует разбор стоимости внедрения ярусов.** G6 и G7 названы
   «дорогими» качественно; сколько именно они стоят в инженерных часах и
   латентности — не измерено.

**Что сделано против предвзятости.** Гипотеза постановки (компактный мандат →
автономия) была проверена на опровержение и **уточнена** по результатам
([40 §7](40-practice-and-cases.md)), а не подтверждена. Перечень смежных
модулей из постановки был изменён (§4), а не воспроизведён. Прецеденты Хаба
