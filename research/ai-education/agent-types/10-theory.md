# Теория: агент, управление и ответственность

## 01. Conceptual Framing

В широком смысле агент наблюдает среду и выбирает действие по некоторой
политике. Политика может быть правилом, поиском, обученной моделью или их
сочетанием. LLM не обязательна для этого определения. В узком прикладном
смысле LLM-агент передаёт языковой модели часть выбора следующего действия.
Это рабочее различение данного исследования, а не попытка установить единое
для всей индустрии значение слова.

**D:** Anthropic различает заранее заданные пути workflow и динамическое
управление агентом; Hugging Face описывает степень влияния LLM на исполнение.
Отсюда H: описывать переданную модели свободу точнее, чем спорить о надписи
«agent» в интерфейсе. Источники:
[Anthropic, Building Effective Agents](https://www.anthropic.com/research/building-effective-agents),
[Hugging Face, smolagents](https://huggingface.co/docs/smolagents/conceptual_guides/intro_agents).

Чат без инструментов может помогать человеку, но сам не меняет внешнюю
среду. Workflow с одним LLM-классификатором может быть эффективной
автоматизацией при минимальной агентности. Скрипт по расписанию может
выполнять сложную работу без LLM. Автономность означает объём разрешённых
решений, а не способность работать без ошибок.

## 02. Объектная модель

| Объект | Содержание | С чем нельзя смешивать |
| --- | --- | --- |
| Задача | Желаемый результат, границы, критерий приёмки | Персона «ты эксперт» не задаёт результат |
| Политика / controller | Выбор следующего шага по текущим сведениям | Модель — только один возможный элемент controller |
| Модель | Вычисление ответа/оценки по входу | Запуск модели не выдаёт ей полномочия |
| Состояние | Наблюдения, выполненные шаги, версии входов, незавершённые действия | История чата не гарантирует полное и актуальное состояние |
| Память | Сохранённое знание/опыт между шагами или задачами | Запись текста не меняет веса модели |
| Инструмент | Операция с контрактом входа, выхода и эффектов | Описание функции не доказывает успешное исполнение |
| Среда | Документы, сайты, БД, люди, устройства, их изменяющееся состояние | Полученная веб-страница — данные, не инструкция оператора |
| Наблюдение | Результат чтения или исполнения, включая ошибку | Намерение вызвать API не равно изменению БД |
| Артефакт | Проверяемый результат с версией и происхождением | Текст об успешном выполнении не заменяет файл/запись |
| Оценщик | Проверка свойства по критерию | LLM-критик не равен независимому оракулу |
| Человек | Постановка цели, спорные решения, предоставление прав, приёмка | HITL не должен означать бесконечное наблюдение каждого токена |

Минимальный цикл: **наблюдать → выбрать шаг → проверить полномочия →
выполнить → проверить фактический результат → обновить состояние**.
Повторять до выполнения критерия, исчерпания бюджета или обнаружения
неразрешимой неопределённости. Ответ «нужны данные» — допустимый выход,
если факты отсутствуют. Разумная остановка входит в качество результата.

**D:** ReAct соединяет рассуждение и действия с получением наблюдений.
Это механизм обратной связи, а не требование раскрывать скрытые рассуждения
модели. Для контроля нужны проверяемые действия, свидетельства и краткое
обоснование решения ([Yao et al., 2022](https://arxiv.org/abs/2210.03629)).

## 03. Состояние, знания и обучение — разные оси

Извлечение документа меняет доступные сведения. Запись в память меняет
контекст будущего запуска. Обучение весов меняет модель. Планирование меняет
предложенную последовательность действий. Ни одно из этих событий само по
себе не гарантирует остальные.

**D:** первоначальный RAG объединяет извлечение с генерацией; динамический
выбор поиска не является обязательной частью определения
([Lewis et al., 2020](https://arxiv.org/abs/2005.11401)).
**D:** Reflexion использует языковую обратную связь и эпизодическую память
между попытками; обратная связь может быть внешней или сгенерированной, веса
не обновляются этим механизмом
([Shinn et al., 2023](https://arxiv.org/abs/2303.11366)).

H: помнить ошибочную догадку вреднее, чем забыть её. Хранить следует отдельно
наблюдение, интерпретацию, степень подтверждения, применимость и дату.
Исправление одной гипотезы должно позволять найти зависящие от неё выводы.

## 04. Автономность как набор полномочий

Вместо одного процента автономности описываются четыре независимых разрешения:

| Решение | Пример ограниченной свободы | Контроль |
| --- | --- | --- |
| Что исследовать | Выбирать запросы внутри темы | Ограничение источников, времени, полноты |
| Как выполнять | Выбирать инструмент и порядок | Контракт инструмента, проверка состояния |
| Что изменять | Создавать черновик в выделенной области | Отдельное разрешение на запись/публикацию |
| Когда считать готовым | Остановиться по машинным критериям | Бизнес-приёмка остаётся отдельным событием |

HITL полезен на **точках решения**: неясная цель, конфликт свидетельств,
необратимый эффект, приёмка результата. Частые бессодержательные подтверждения
плохо контролируют работу. Проверка перед публикацией должна показывать
сам публикуемый результат и его основания. Для чтения и обратимых черновиков
можно дать более широкую свободу, если это соответствует задаче и данным.

## 05. Почему сложность иногда помогает, иногда мешает

Декомпозиция уменьшает локальный контекст, но добавляет передачу данных и
слияние. Параллельные независимые исследования могут сократить критический
путь. Параллельное изменение одного понятия разными исполнителями может
увеличить число противоречий. Роли «автор» и «критик» создают организационное
разделение, но не статистическую независимость: общая модель и общий источник
могут породить общую ошибку.

**R:** MAST исследует отказы координации, спецификации и проверки в нескольких
мультиагентных системах. Это свидетельство наличия организационных рисков,
а не оценка частоты ошибок всех будущих систем
([Cemri et al., 2025](https://arxiv.org/abs/2503.13657)).

H: сравнивать усложнение с сильной простой альтернативой при равном бюджете.
Например, critic-loop против одиночного прохода плюс внешний тест; команда
против одного агента с теми же источниками и временем. Дополнительный токен
или агент — расход, выигрыш измеряется принятым результатом.

## 06. Качество входа и инфраструктура

«Толерантность к промпту» не является постоянным свойством типа. В карточках
это качественная оценка: что система может уточнить, а что нужно задать
явно. Она зависит от модели, инструментов, знакомости домена, контекста и
критерия успеха. Нельзя обещать, что планировщик восстановит отсутствующую
цель или что RAG исправит неверное определение сущности.

Локально/облако/гибрид описывает размещение **каждого компонента**, а не агента
в целом. Локальный controller с облачной моделью передаёт ей вход; локальная
модель с внешним поиском не является полностью изолированной системой.
Планирование требует состояния и возобновления; фон — очереди и защиты от
повторного эффекта; исполнение кода — изоляции; UI — управляемой сессии;
робот — сенсоров и ограничений реального времени. Эти требования следуют из
эффектов действия, независимо от бренда.

## 07. Проверяемые гипотезы и переход к решениям

| H | Что предсказывается | Что опровергнет рекомендацию в заданном контексте |
| --- | --- | --- |
| H1: фиксированный маршрут предпочтителен при известном процессе | Меньше вариативность исполнения при достаточном качестве | Агент при равном бюджете устойчиво лучше справляется с реальными вариациями |
| H2: retrieval нужен при зависимости от внешних фактов | Лучше подтверждённость и актуальность | Пропуски поиска/неверное связывание делают принятые ответы хуже baseline |
| H3: команда полезна при независимых подзадачах | Выигрыш времени/покрытия превышает цену слияния | Повторы, конфликты и проверка уничтожают этот выигрыш |
| H4: автономию нужно ограничивать по последствиям | Меньше неприемлемых эффектов при приемлемом участии человека | Контроль не ловит опасные решения или делает задачу практически невыполнимой |

Это проверяемые правила проектного выбора, а не новые эмпирические законы.
Они развёрнуты в [матрице решений](30-decision-framework.md).
Воспроизведённое противоречие возвращается в теорию по
[протоколу обратной связи](50-open-research.md#feedback).
