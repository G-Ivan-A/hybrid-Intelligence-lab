## Как читать разметку

Для каждого кейса указаны:

- **операционализации** из
  [20-taxonomy.md](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/research/reputation-technologies/gra-research-program/20-taxonomy.md),
  которые неявно использует кейс;
- **конкурирующая модель**, которую лектор не обсуждает, но исследователь
  должен иметь в виду;
- **опровергающее условие** — то, что уже есть в кейсе для чата;
- **урок для теории (P5)** — что кейс говорит о модели и что вернуть в
  [10-theory.md](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/research/reputation-technologies/gra-research-program/10-theory.md).

## Кейс А. Переговоры с холдингом

| Элемент | Разметка |
| --- | --- |
| Масса | M2 (институциональная: инженер подписывает технические требования) против M2 директора по закупкам. Гипотеза кейса о том, чья M5 (влияние на это решение) выше |
| Дистанция | D2 (информационная: общая конференция, канал «инженер — конкурент») и D3 (социальная: слабая связь через технолога `[650:Г10]`). D1 не играет: все в одном регионе |
| Полярность | P1: связь «инженер — конкурент» +1; связь «инженер — мы» «?». P4: цепочка событий с датами |
| Конкурирующая модель | H0: «решает цена и тот, у кого должность выше». H5: инженера окружают другие поставщики, и наш вход зависит от того, кто «ближе» |
| Опровергающее условие | (А) директор по закупкам единолично утверждает перечень; (Б) конференция после обновления прайса — оба уже в кейсе |
| Урок для теории (P5) | Кейс не различает D2 и D3: короткая дистанция может быть и каналом, и доверием. Это аргумент в пользу HD1 как открытого вопроса, а не готового ответа |

## Кейс Б. Банк и пост предпринимателя

| Элемент | Разметка |
| --- | --- |
| Масса | M2 и M3 ассоциации: она приводит клиентов и её слушает региональная власть |
| Дистанция | D2 от пресс-службы до ассоциации велика; короткий путь — через корпоративного клиента в правлении (D3) |
| Полярность | P1: знак ассоциации движется от 0 к −1. **P2 и P3 (гипотеза направленности HP-D):** поток в среде — от предпринимательских каналов к ассоциации и дальше к власти. Пресс-релиз банка идёт против этого потока. Член правления — узел, связь которого с ассоциацией направлена «по потоку» |
| Конкурирующая модель | H0: «негатив гасится охватом ответа». H1 без направления: «нужно увеличить массу сигнала». H4 предсказывает иное: сигнал против потока не дойдёт при любом разумном охвате, нужен сонаправленный вектор |
| Опровергающее условие | (А) интенсивность связей ассоциации с банком не изменилась — уже в кейсе. Для HP-D отдельно: ответ пресс-службы, сопоставимый по массе и охвату, вернул знак ассоциации без обращения через члена правления |
| Урок для теории (P5) | Кейс — главная иллюстрация того, что Полярность не сводится к знаку. Метафора магнитного поля здесь — исследовательская метафора: «по потоку» и «против потока» нужно операционализировать (кто кому пересылает, кто на кого ссылается) |

## Кейс В. Внутренний конфликт выходит наружу

| Элемент | Разметка |
| --- | --- |
| Масса | M3 мастеров участков: они мосты между цехом, семьями и городом |
| Дистанция | D2 и D3: у мастеров самая короткая дистанция до рабочих. D1 значим: город и завод — одно место |
| Полярность | P1 мастера; P4 — гипотеза последовательности «сначала мастера, потом город». P2: поток идёт снизу вверх (цех → семьи → паблик → газета → администрация), рассылка идёт сверху вниз |
| Конкурирующая модель | H0: «конфликт определяется числом негативных постов». Альтернатива: решает сама мера (премии), сеть ни при чём |
| Опровергающее условие | Мастера пересылали рассылку без негативного комментария, а знак города всё равно сменился |
| Урок для теории (P5) | Кейс показывает, что масса узла зависит от позиции в сети (M3), а не от должности (M2). Довод в пользу разведения массы и влияния (T4) |

## Кейс Г. Медиабюджет МСП без контрактов

| Элемент | Разметка |
| --- | --- |
| Масса | Масса аудитории (охват) против массы узлов решения: эксперт, комиссия, технический комитет, фонд. Это M2 и M5 против M4-подобного охвата |
| Дистанция | D2 до узлов решения не сократилась: ни один эксперт не видел решение в работе. Референс-визит сокращает D2 и D3 |
| Полярность | P1 «?» у всех узлов решения. Метрика кейса — переход «? → +1» |
| Конкурирующая модель | H0 — ровно то, что кейс опровергает: охват и тональность. Альтернатива: проблема в продукте или цене, а не в связях |
| Опровергающее условие | Эксперты регулярно читают издание и уже видели решение — уже в кейсе |
| Урок для теории (P5) | Кейс — прямое сравнение H0 и структурной гипотезы на одном исходе. Это шаблон для критерия K3 |

## Протокол соисследователя

Карточка для одного-двух слушателей, откликнувшихся на целевое действие Дня 1.
Это не пилот и не продажа: протокол проверяет гипотезы на одной реальной
ситуации и даёт данные для открытых вопросов
[50-open-research.md](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/research/reputation-technologies/gra-research-program/50-open-research.md#1-открытые-вопросы).

1. **Ситуация.** Одно решение с исходом в ближайший месяц: переговоры, тендер,
   конфликт или бюджет. По желанию обезличивается.
2. **Карта.** 5–15 узлов. Для каждого: масса (какие компоненты M1–M4 видны) и
   влияние на это решение (M5) — раздельно, порядковыми оценками.
3. **Дистанция.** По каждой связи — минимум две оси: D1 и D2. D3 — если есть
   основания. Не сводить в одно число.
4. **Полярность.** Знак или «?» и, если видно, направление: кто кому передаёт
   сигнал.
5. **Гипотеза и опровержение.** Одна гипотеза о том, что определит исход, и
   опровергающее условие — **до исхода**. Плюс прогноз базовой линии H0
   (охват и тональность).
6. **ИИ.** Агент собирает события и предлагает альтернативы. Каждый факт проходит
   гейт G1–G6
   ([30-decision-framework.md, §5](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/research/reputation-technologies/gra-research-program/30-decision-framework.md#5-гейт-для-выводов-ии-агентов)).
7. **Этика.** Только «белые» источники: публичная профессиональная активность
   (граница кейса А, `[653:М8]`).
8. **Итог.** После исхода: какая гипотеза — GRA или H0 — предсказала лучше, и
   дала ли карта вопрос, которого раньше не было. Результат записывается по
   таблице исходов
   [§3 файла 30](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/research/reputation-technologies/gra-research-program/30-decision-framework.md#3-процедура-проверки-гипотезы),
   включая негативный.
