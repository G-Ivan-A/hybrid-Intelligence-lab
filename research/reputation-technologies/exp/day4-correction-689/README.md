# День 4: исправление границы GRA и гейт-проверка issue #689

Задача — [#689](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/issues/689). Скрипт проверяет три файла issue: [разбор провала интерпретации ИИ](../../2026-11-03-day4-ai-interpretation-analysis.md), [Вариант 2 обоснования Дня 4](../../2026-11-03-day4-rationale-and-method-v2.md) и [RFC для готовой колоды](../../2026-11-03-day4-crisis-mitigation-rfc.md). Ещё он следит, чтобы [Вариант 1](../../2026-11-03-day4-rationale-and-method.md) остался без изменений. Смысл разбора и уместность замен проверяются чтением; скрипт проверяет структуру, дословные цитаты и жёсткие ограничения issue.

| Файл | Что делает |
| --- | --- |
| `check-day4-689.py` | Гейт-проверка трёх файлов и Варианта 1 и самопроверка на искусственных повреждениях |
| `mutation_reasons_689.py` | Печатает первую ошибку, которую вызывает каждое повреждение самопроверки: видно, что повреждение отклонено по своей причине, а не случайно |
| `verify_deck_quotes_689.py` | Сверяет каждую строку «Было» таблиц замен RFC с `[SLIDE_TEXT]` своего слайда в колоде #688 (коммит `9d1fc9f`) и печатает, как меняется длина строки |
| `issue-689-before.log` | Вывод проверки на `main` до #689 |
| `issue-689-after.log` | Вывод проверок после #689 |

`check-day4-689.py` проверяет:

- Вариант 1 байт в байт совпадает с файлом, который принял PR #686: git-хеш `6bae8fc84fc1d5d9d8b483f24aa3473a6768b54e`;
- у трёх новых файлов `source` — issue #689; ссылки — полные URL, файлы и якоря репозитория, на которые они ведут, существуют; черновых HTML-комментариев нет;
- разбор: все разделы направления 1 — суммаризация, примеры, корневая причина, пословица «Заставь дурака молиться, он и лоб расшибет» с таблицей ролей и не меньше чем тремя механизмами; не меньше 20 цитат Варианта 1 с номерами строк, и каждая цитата стоит в своей строке Варианта 1; в примерах есть «потому что → поэтому», масса, дистанция и полярность; отсутствие файла диалога оформлено отклонением в формате фаундера, а пункт 7 гейта говорит «неприменимо», а не «удалён»; в гейте ровно семь пунктов `[x]`;
- Вариант 2: 21 карточка подряд, у каждой ровно четыре поля — «Название», «Суть», «Условие применения» в виде «Если …, применяем …», «Визуальный маркер»; в перечне технологий нет слов «масса», «дистанция», «полярность», «статус», меток `VERIFIED`, `PARTIAL`, `CONFLICT`, слова GRA и связок «потому что», «поэтому»; отклонение от примеров условий записано в формате фаундера; лектор на Дне 1 только согласился, что GRA собирает данные о нём, и на Дне 4 не применяет GRA к себе; в гейте шесть пунктов `[x]`;
- RFC: диагноз — колода сгенерирована, структура не меняется; фраза фаундера дословно, ровно одна, на слайде 17 колоды; P0 — ровно две замены, заголовок слайда 19 становится «Правило выбора стиля»; список P1 оформлен отклонением в формате фаундера; ни одна замена не повторяет исходную строку; есть постоянная ссылка на колоду #688; вывод говорит о кредитах, отказе от новой генерации, эфире и тексте слайда 19; в гейте шесть пунктов `[x]`.

Колоды #688 ещё нет в `main`, поэтому `verify_deck_quotes_689.py` не входит в CI: он читает колоду из git после `git fetch origin pull/688/head` или из файла, переданного аргументом.

Запуск из корня репозитория:

```bash
python3 -I research/reputation-technologies/exp/day4-correction-689/check-day4-689.py --self-test
python3 -I research/reputation-technologies/exp/day4-correction-689/mutation_reasons_689.py

```
