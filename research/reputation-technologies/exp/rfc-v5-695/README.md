# День 4, Вариант 5: RFC точечных замен в колоде v4 и гейт-проверка issue #695

Задача — [#695](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/issues/695). Колода [v4](../../2026-11-03-day4-presentation-gamma-v4.md) не перегенерируется: [RFC](../../2026-11-03-rfc-presentation-update-v5.md) перечисляет точечные замены «Было → Стало» с обоснованием, а скрипт проверяет, что замены дословно опираются на v4 и дают колоду v5 по правилам #695. Насколько верны сами источники и статусы, скрипт не оценивает: это проверяется чтением [модуля v0.2](../../image-technologies/00-introduction.md) и сверкой цитат.

| Файл | Что делает |
| --- | --- |
| `build-rfc-695.py` | Источник замен: список правок с обоснованиями; проверяет, что каждая цитата «Было» встречается ровно один раз в своей строке v4, и переписывает раздел 2 RFC; `--preview PATH` пишет получившуюся колоду v5, `--no-rfc` — без записи RFC |
| `check-rfc-695.py` | Гейт-проверка RFC и колоды v5, которую дают его строки, и самопроверка на искусственных повреждениях; независим от `build-rfc-695.py` — читает таблицу из самого RFC; `--write-v5 PATH` пишет колоду v5 |
| `mutation_reasons_695.py` | Печатает первую ошибку, которую вызывает каждое повреждение самопроверки: видно, что повреждение отклонено по своей причине, а не случайно |
| `issue-695-before.log` | Вывод проверки до #695: без RFC и на черновике RFC, который меняет только хвост промптов |
| `issue-695-after.log` | Вывод проверки, причины отклонения повреждений и гейт #693 на неизменённой колоде v4 после #695 |

`check-rfc-695.py` проверяет:

- колода v4 совпадает с коммитом `f3af657` по SHA-256 — RFC цитирует её, а не перегенерирует;
- в RFC разделы «1. Обоснование», «2. Таблица замен (Diffs)», «3. Визуальные правила» по порядку; обе таблицы раздела 2 — с колонками «№ · Слайд · Поле · Было · Стало · Обоснование»; строки G-01, V5-001…, S-001… подряд, у каждой — обоснование;
- каждая ячейка «Было» — `[v4:Ln](постоянная ссылка на строку n коммита f3af657) «цитата»`, номер в подписи и в ссылке совпадают, цитата ровно один раз встречается в строке n; колонки «Слайд» и «Поле» совпадают с местом строки в v4 (служебные разделы — «—»); фрагменты одной строки не пересекаются;
- строки применяются к v4 справа налево, затем G-01 заменяет хвост во всех 27 промптах изображений; получившаяся колода v5 проходит гейт [#693](../day4-v4-693/README.md) с правилами #695: статусы `VERIFIED`, `PARTIAL`, `CONFLICT` разрешены, «консервативность» — не кейс курса, обязательные технологии — Й. Иттен, Ватерман и Цингель (цвет), Беляева-Экземплярская и «Гид по стилю» (форма), «Гид по стилю» и Трубецкова (стиль), «Гид по стилю» (аксессуары), слайд 16 называет «Гид по стилю» без ВШСДТ, хвост промпта — визуальное правило #695, промпт Gamma — «навеянная идеей ар-деко»;
- на слайдах 5, 10, 14, 16 и 20 дословно стоит формула #695 *Технологии, используемые в НИА "Гид по стилю" (на базе которых впоследствии образовался ряд профильных школ)*; в колоде v5 и в колонке «Стало» нет ВШСДТ, Туркенич, Маменко и авторов справочника НИА (без учёта регистра), а Ваттерман, Джексон, Моллой и Jewelrygram остаются только в цитатах раздела решений;
- все ссылки колоды v5, колонки «Стало» и собственного текста RFC — полные `https://` без блогов, личных журналов, файловых библиотек, сайтов школ, Википедии и сокращателей ссылок; цитаты v4 в «Было» сохраняют прежние ссылки дословно;
- профиль статусов в выводе каждого слайда технологии и в таблице этапа 2 RFC равен профилю его карточек в таксономии; каждая строка с `PARTIAL` или `CONFLICT` — в колоде и в таксономии — несёт фразу *Механизм восприятия реален, но направление и сила зависят от контекста, что требует проверки глазом и опытом.*;
- раздел 3 дословно приводит визуальное правило #695; в промптах изображений, промпте Gamma и таблице фото нет Нью-Йорка, Пекина, Баухауза и Neue Sachlichkeit;
- раздел 1 формулирует не меньше семи отклонений по правилу #695 «Я предлагаю скорректировать [X], потому что вариант [Y] эффективнее решает задачу [Z]», и каждое слово в слово совпадает с модулем; `source` RFC — issue #695, `source` колоды v5 называет #695; ссылки и якоря репозитория существуют; пункты гейт-проверки RFC отмечены `[x]`.

В режиме `--self-test` каждое из искусственных повреждений должно быть отклонено; их число печатает последняя строка вывода, а `mutation_reasons_695.py` показывает, какой проверкой отклонено каждое.

## Запуск из корня

```bash
python3 -I research/reputation-technologies/exp/rfc-v5-695/check-rfc-695.py --self-test
python3 -I research/reputation-technologies/exp/rfc-v5-695/mutation_reasons_695.py
python3 -I research/reputation-technologies/exp/rfc-v5-695/build-rfc-695.py --no-rfc
```

Ожидаемый вывод первой команды — строки `PASS:` и `PASS: 53 broken fixtures rejected`. Третья команда проверяет, что список правок построителя по-прежнему применяется к v4; без `--no-rfc` она заново пишет раздел 2 RFC, и `git diff` после неё должен быть пустым.

## Воспроизведение issue #695

`issue-695-before.log` — два прогона до готового RFC. Первый — без файла RFC, как на коммите `0acad42`: проверка падает с `file not found`. Второй — на черновике RFC, в котором есть только строка G-01: хвост промптов уже следует визуальному правилу #695, но содержание v4 — нет. Колода называет ВШСДТ, Школу Туркенич и авторов справочника, нет формулы НИА и обязательных технологий #695, ссылки ведут на блоги, сайты школ и Википедию, в концепциях изображений остались Баухауз и Neue Sachlichkeit, а в выводах слайдов технологий нет профилей статусов.

`issue-695-after.log` — вывод после #695: все проверки проходят, все 53 повреждения самопроверки отклонены, у каждого своя причина, а гейт #693 на неизменённой колоде v4 по-прежнему проходит.
