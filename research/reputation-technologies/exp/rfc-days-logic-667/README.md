# Логика Дней 1–3: проверка issue #667

Родительский документ — [RFC: логический каркас Дней 1–3 на 90 минут](../../2026-10-12-rfc-days-1-3-logic.md), задача — [#667](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/issues/667). Скрипт проверяет форму RFC по критериям приёмки issue, а не обучающий эффект. Обучающий эффект проверяется репетицией с секундомером и первым эфиром; см. раздел «Как опровергнуть этот RFC».

`check-rfc-logic.py` проверяет:

- первый раздел документа — «КРИТИЧЕСКАЯ АППЕЛЯЦИЯ», есть Executive Summary;
- для каждого из трёх дней не больше 30 слайдов: 5 вводных, 15–20 основных, 1–4 финальных, номера подряд;
- у каждого слайда есть поля «Зачем этот слайд?», «Нарративная связь» и «Формат и время»;
- минуты слайдов и резерв дня дают ровно 90, голосований в чате не больше четырёх;
- таблиц нет до раздела «Приложение»;
- в раскладке дней нет промптов изображений;
- нет ссылок на локальные файлы программы, есть ссылка на Техноград;
- отклонённый RFC #665 и папка `presentation-rfc/` помечены `status: rejected`.

В режиме `--self-test` скрипт дополнительно воспроизводит исходную проблему: отклонённый RFC #665 должен не пройти контракт #667. Кроме того, восемь искусственных повреждений нового RFC должны быть отклонены.

## Запуск из корня

```bash
python3 -I research/reputation-technologies/exp/rfc-days-logic-667/check-rfc-logic.py --self-test
```

Подсчёт объёма презентаций до и после PR #666, на который ссылается аппеляция:

```bash
for f in 2026-10-07-day1-presentation-653.md 2026-10-30-day2-presentation.md 2026-11-02-day3-presentation.md; do
  for c in 6428ade f3d67da; do printf '%s %s ' "$c" "$f"; git show "$c:research/reputation-technologies/$f" | wc -w; done
done
```

Презентации и сценарии лектора этим контейнером не меняются: issue #667 запрещает их правку до утверждения RFC фаундером.
