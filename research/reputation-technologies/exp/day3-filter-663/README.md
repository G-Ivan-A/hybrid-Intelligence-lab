# exp: day3-filter-663

Evidence container для пакета Дня 3 курса, начиная с
[`../../2026-11-02-day3-rationale-and-method.md`](../../2026-11-02-day3-rationale-and-method.md),
по issue [#663](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/issues/663).

> **Ссылки.** Issue #663 требует абсолютных ссылок. Относительная ссылка на
> родительский отчёт выше — вынужденное исключение: её форму машинно проверяет
> [`tools/validate-evidence-structure.sh`](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/tools/validate-evidence-structure.sh).

## Что здесь лежит

| Файл | Что делает |
| --- | --- |
| `check-day3.sh` | Проверяет три документа Дня 3: нет оценочных прилагательных из запрета issue, нет относительных ссылок, все пять дословных тегов есть в сценарии, 30 слайдов в презентации и сценарии, формулировки программы Дня 3 есть в документах 1 и 2. Проверяет разметку достоверности по [комментарию владельца в PR #664](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/pull/664#issuecomment-6111152651): в Промпте-фильтре есть блок «РАЗМЕТКА ДОСТОВЕРНОСТИ» и правило «ты обязан явно указать причину низкого уровня достоверности», то же правило есть в Промпте-разведчике Дня 2, в кейсе 1 есть ссылки на https://kad.arbitr.ru/ и https://fssp.gov.ru/iss/ip, нет «платы за вход» — коммерческого условия без источника. Проверяет, что пункт «Сверьте с юристом» в подготовке лектора Дней 3 и 2 называет все нормы из пункта «Правовые нормы» в документе 1 того же дня — границы для юриста: в Дне 3 — и 381-ФЗ с 98-ФЗ кейса 1. Ловит вертикальную черту внутри кода в строках таблиц: она делит ячейку. Печатает число произносимых слов по слотам сценария для проверки плотности |
| `test-check-day3.sh` | Самопроверка `check-day3.sh`: на временной копии документов по одной вносит нарушения разметки достоверности — убирает правило о причине статуса из Промпта-фильтра и из Промпта-разведчика Дня 2, убирает ссылку на kad.arbitr.ru, добавляет строку таблицы с «платой за вход» и строку с вертикальной чертой внутри кода, убирает нормы кейса 1 из сверки с юристом в сценариях Дней 3 и 2, в том числе когда выше пункта «Правовые нормы» стоит посторонняя строка с теми же словами, — и ждёт на каждое код 1 и нужную строку `FAIL`. Исходные документы не меняет |

## Запуск

```bash
bash research/reputation-technologies/exp/day3-filter-663/check-day3.sh
bash research/reputation-technologies/exp/day3-filter-663/test-check-day3.sh
python3 -I research/reputation-technologies/exp/gra-research-program-657/check-gra-anchors.py . \
  research/reputation-technologies/2026-10-07-day1-*.md \
  research/reputation-technologies/2026-10-30-day2-*.md \
  research/reputation-technologies/2026-11-02-day3-*.md
```

Ожидаемый результат на 2026-10-11: `check-day3.sh` и `test-check-day3.sh`
завершаются с кодом 0 и не печатают строк `FAIL`. Самые плотные слоты
сценария — 19:08–19:15 (429 слов на 7 минут) и 19:21–19:29 (428 слов на
8 минут): при темпе 120–130 слов в минуту речь занимает 3,3–3,6 минуты,
остальное — голосование в чате, демонстрация экрана и паузы.
`check-gra-anchors.py` печатает `bad: 0`: после слияния
[PR #662](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/pull/662)
ссылки на документы Дня 2 открываются. Без списка файлов после `.` скрипт
ничего не проверяет и тоже печатает `bad: 0`, поэтому файлы перечислены явно.
