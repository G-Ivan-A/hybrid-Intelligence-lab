## Summary

Предлагается слой правил сотрудничества в новом файле
`ai-rules/agent-collaboration-rules.md` и краткая норма в общем слое
`AGENTS.md`. Слой содержит:

- стратегическую проверку решения (тактика против стратегии);
- семь правил коммуникации с формой проверки;
- профили трёх режимов с бюджетом токенов;
- обязательный креативный протокол: гипотезы, внешние источники, синтез кейсов
  с негативными кейсами, оцифровку, журнал решений, подзадачи;
- правило обоснованных задач;
- неблокирующие якоря синхронизации;
- реестр анти-паттернов.

Два противоречия действующих контрактов (K-1 — определение `Hybrid`, K-2 —
глоссарий о глубине) записаны в ADR-021 и не переписаны без решения владельца.

## Motivation

### Честная оценка зрелости

Issue требует честно ответить, близки ли контракты к совершенству. Ответ
разный по разным темам.

| Требование #625 | Что уже есть | Оценка |
| --- | --- | --- |
| Апелляция, критическое мышление | Контракт апелляции; `<hybrid_work>`; «отсутствие апелляции — утверждение» | Зрелое. Не переписывается. |
| Двухфакторное подтверждение | Контракт эскалации, закрытый перечень автономии, human decision rights | Элементы есть, но не собраны в правило. «Перед движением дальше» буквально невыполнимо: агент не перезапускается комментарием. |
| Тактика против стратегии; концепция **и видение** | Нормализация цели читает только концепцию | Пробел G-1 |
| Запрет пустого исполнения, подхалимства; краткость | Косвенно, через апелляцию | Пробел G-2 |
| Три режима с чёткими границами и бюджетом токенов | Таблица инициативы; бюджет «наибольший / средний / наименьший» | Бюджет не раскрыт в обязательства. Найдены противоречия K-1, K-2. |
| Внешние источники и синтез кейсов в `Creative` | Нет | Пробел G-3 |
| Негативные кейсы | ADR-014 закрывает только первую ошибку БА и только для мета-модели БА | Пробел G-4 |
| Правило обоснованных задач | «Число задач не ограничено» | Пробел G-5: нет фильтра |
| Якоря синхронизации | Две точки контроля, «гейтов не вводится» | Пробел G-6 |

**Вывод.** Контракты исполнения (апелляция, автономия, эскалация, верификация)
близки к целевому состоянию и не меняются. Контракты партнёрства отсутствуют.

Откладывание не оправдано по трём причинам:

1. G-4 уже привёл к повторной сборке модели БА (ошибка 2 в issue).
2. Следующие модели Хаба строятся тем же способом.
3. Стоимость правила — один файл и несколько строк точки входа.

### Почему недостаточно текста issue

Правила в issue описывают намерение, но не форму проверки. Без строки «Как
проверяется» и регрессионного теста норма остаётся рекомендацией. Это прямо
показывает кейс `docs/contracts/`: каталог прошёл 42 зелёных валидатора, потому
что запрет существовал только как текст (находка F7 в `B-116`).

## Goals and Non-goals

**Goals.**

- Зафиксировать в `AGENTS.md` и `ai-rules/` все семь пунктов критериев
  готовности #625.
- Спроектировать собственный вариант креативного режима и проверить его
  стресс-тестами до внедрения.
- Сделать негативный опыт проверкой контракта, а не памятью участников.
- Сохранить модель исполнения: две точки контроля, без новых гейтов.

**Non-goals.**

- Не переписывать определения `Hybrid` в Agent Work Rules и AI Governance и
  строку глоссария (K-1, K-2) — решение за владельцем.
- Не менять закрытый перечень автономии ADR-010.
- Не вводить машинную проверку тела PR: шаблона PR в Хабе нет, это отдельная
  задача (`B-197`).
- Не собирать реестр негативных кейсов практики БА: нужен доступ к корпусу
  `mango_ba_prompts` (`B-198`).

## Proposal

### Вариант креативного режима и его эволюция

Исполнитель сначала спроектировал вариант v0 и атаковал его стресс-тестами
(раздел ниже). Итоговая норма — v1. Изменения v0 → v1 и их причины:

| Элемент | v0 | v1 | Что заставило изменить |
| --- | --- | --- | --- |
| Синхронизация с человеком | Блокирующий гейт после сбора данных (так предлагал ИИ-ассистент в диалоге фаундера) | Неблокирующие якоря A-1…A-6; блокирует только C-5 | H3.3: агент не перезапускается комментарием, дополнительные гейты запрещены |
| Бюджет `Creative` | «Максимум токенов» как цель | Максимальный бюджет — разрешение; качество измеряется покрытием гипотез и кейсов | H2.1: METR — ощущаемая польза ≠ измеренной; Goodhart |
| Самопроверка | «Перепроверить решение» | Проверка только с внешней обратной связью: тест, валидатор, источник | H2.4: Huang et al. — самокоррекция без обратной связи ухудшает результат |
| Размещение | Три файла: коммуникация, режимы, креатив | Один файл + норма в `AGENTS.md` | H5.1–H5.2: бюджет контекста; Anti-Inflation |
| `Hybrid` | Переписать определение «по частям» | Обе нормы совместимы в профиле; конфликт вынесен в ADR-021 | H5.5: запрет issue менять контракт без решения владельца |
| Расширяющие предложения | Исполнять, если агент уверен | Предлагать с пометкой; исполнять только внутри цели и проектного разрешения | H1.3: «Границы проекта» в `<hybrid_work>` |
| Источник «premortem +30% точности» | Цитата по памяти | «~30% больше названных причин», без оценки точности | Верификация источников (раздел ниже) |

## Стресс-тесты

Выполнены по [Adversarial Stress Testing](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/ai-rules/adversarial-stress-testing.md).

**Вход.**

- Источники истины по приоритету: issue #625 → `AGENTS.md` → Agent Work Rules
  → ADR-010 → AI Governance → глоссарий.
- Граница проверки: текст норм и их совместимость с моделью исполнения.
  Поведение агентов на прогонах не измерялось.
- Перспективы: архитектурная, операционная, security, human-governance.

### H1. Правила C-1…C-7 совместимы с моделью исполнения и не вводят новый гейт

| ID | Стресс-сценарий | Перспектива | Evidence | Вердикт |
| --- | --- | --- | --- | --- |
| H1.1 | C-5 требует подтверждения «перед движением дальше», но остановленный агент не получает ответа | human-governance | Agent Work Rules §Специфика: комментарий без restart не поручение | ⚠️ Блокируется только спорная часть, остальное доставляется; решение — ответ или merge |
| H1.2 | C-1 превращается в возражения ради демонстрации независимости | операционная | C-2 требует альтернативу и evidence | ⚠️ Проверка только human-only |
| H1.3 | C-4 «результат важнее буквы» используется для обхода явного запрета | security | Текст C-4 сохраняет закрытый перечень; ADR-010 | ✅ |
| H1.4 | Запрет извинений скрывает ошибки системы | human-governance | C-7: формат «факт → причина → решение»; S-14 | ✅ |
| H1.5 | C-6 «краткость» противоречит максимальной глубине `Creative` | архитектурная | C-6 ограничивает повторы, а не глубину | ✅ |
| H1.6 | Disagree and commit блокирует возражение на новом этапе | операционная | C-7: новый аргумент открывает позицию заново | ✅ |

Итог H1: ✅ 4 / ⚠️ 2 / ❌ 0. Гипотеза держит. Остаточный риск —
human-only проверка C-1/C-2.

### H2. Креативный протокол с максимальным бюджетом повышает качество, а не только расход

| ID | Стресс-сценарий | Перспектива | Evidence | Вердикт |
| --- | --- | --- | --- | --- |
| H2.1 | Токены тратятся без роста качества, а участники ощущают пользу | операционная | S-13 | ⚠️ Качество меряется покрытием гипотез и кейсов (M-2, M-4), не расходом |

## Alternatives

| Отложить изменения | Пробел G-4 уже привёл к повторной работе. Стоимость внедрения мала. |
| Встроить всё в `agent-work-rules.md` | Превышение бюджета размера файла глубины 0. |

| Блокирующие гейты | Противоречат модели исполнения и запрету дополнительных гейтов. |
| Норма только в `ai-rules/`, без `AGENTS.md` | Issue требует фиксации в `AGENTS.md`. Точка входа без маршрута не приводит агента к норме. |
| Норма только в Хабе, без шаблонов | Слой общий и должен доходить до спиц. Тактика и стратегия важнее всего именно в проектах. |

| --- | --- |
