# Вынос GRA из Хаба: сверка полноты и что делать с остатком

## Summary / BLUF

**Вынос текущих документов завершён, а вынос домена — нет.** Все 34 текущих
документа, перенесённые в `aether-orbis-gra`, не менялись в Хабе после
коммита-источника. Ни один перенос не устарел. Тем не менее домен
`research/reputation-technologies/` по-прежнему занимает в Хабе 173 файла:
15,9 % отслеживаемых файлов и 33,5 % байтов. На него завязаны 19 шагов CI
(28 % времени задания `validate`) и 34 файла Хаба вне домена. Перенести осталось
немного:

1. документ цитат курса `2026-11-01-course-quotes-days-1-4-alce.md`, созданный
   после снимка спицы;
2. четыре открытые задачи Спринта 29: юридическая проверка кейсов, гипотезы
   HP-D и HM-I, холодный поиск, а также решение по B-232. У спицы нет бэклога,
   поэтому сейчас им некуда переехать.
3. Два файла требуют решения владельца: «глобальные» они или проектные.

**Главные блокеры очистки найдены измерением, а не чтением.** Их четыре.

- В спице 167 плавающих ссылок `blob/main` на домен Хаба. Любое перемещение
  файла в Хабе ломает их.
- На 72 из 80 единиц домена ссылаются исторические записи: CHANGELOG, ADR,
  RFC, аудит, анализы. Действующий стандарт выбытия запрещает удалять такие
  пути без compatibility redirect.
- GitHub не перенаправляет удалённый путь. Даже объявленная запись
  `path_migrations` даёт на `blob/main` ответ 404.
- Файл исследования о конкретном человеке (PII) нельзя архивировать: его можно
  только удалить.

**Рекомендация.** Предварительная диспозиция (73 файла удалить, 61
заархивировать, 34 заменить указателем) исполняется **после** трёх действий:
закрепить ссылки спицы на SHA, переписать живые ссылки Хаба и ввести в
стандарт манифестное надгробие. Архив лучше держать **не каталогом в дереве, а
аннотированным тегом с манифестом**. Каталог-архив оставляет в контексте агента
и в проверках треть байтов Хаба и при этом не спасает ни одной ссылки
`blob/main`, потому что путь всё равно меняется. Дорожная карта — в
[RFC #721](../rfc/2026-11-04-rfc-gra-extraction-completion-and-hub-cleanup.md),
норма архива — в
[ADR-022](../adr/2026-11-adr-022-hub-archive-and-extraction-redirect.md).

## Context / Scope

[Issue #721](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/issues/721)
требует проверить полноту выноса практик репутационных технологий в
`aether-orbis-gra`. По итогам надо решить, что удалить из Хаба, что сложить в
общий архив, который валидаторы не читают, и что оставить в `research/` как
глобальное исследование. Попутно нужно сверить экосистему и параллельную работу.

[RFC #715](../rfc/2026-11-02-rfc-hub-governance-optimization-roadmap.md)
исключил домен из своей дорожной карты (исключение A-4: «не создаёт задач на
перенос, заморозку или ре-импорт материалов `research/reputation-technologies/`»).
Поэтому настоящая сверка — первый документ Хаба, который рассматривает домен
целиком.

### F-3. Переносятся ли самопроверки курса

[`spoke-guard-replay.py`](../../research/hub/exp/gra-extraction-cleanup-721/spoke-guard-replay.py)

| Проходят на обеих копиях | 6 | Проверяемые инварианты сохранились в копиях спицы |

### F-5. Исторические записи против «удалить малоценное»

Стандарт выбытия разрешает физическое удаление, только когда «на путь
артефакта нет ссылок из исторических документов (accepted/принятые ADR, RFC,
merged PR-описания, changelog-записи)»
([Deletion Rules, условие 2](../../standards/artifact-deprecation-standard.md#deletion-rules)).
Измерение: на 72 из 80 единиц (159 файлов) ссылаются CHANGELOG или записи в
`docs/{adr,rfc,audit,analysis,report}/`. Все 19 единиц из списка DELETE
упомянуты в CHANGELOG. **Значит, по действующей норме удалить нельзя ни одну из
них**, пока адрес не заменён compatibility redirect. А redirect стандарт
определяет только как «файл остаётся по прежнему пути», то есть по одному файлу
на каждый путь.

Гипотеза владельца («малоценное свидетельство отвергнутого можно удалить»)
совпадает с индустриальной практикой, но только в одной части:

- Google docguide требует «Delete Dead Documentation»
  ([источник](https://google.github.io/styleguide/docguide/best_practices.html#delete-dead-documentation)).
- Nygard требует отвергнутое решение «keep the old one around, but mark it as
  superseded»
  ([источник](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions)).

Отсюда граница: удаляются рабочие версии и проверки задач (R9), а записи
решений, в том числе отклонённые, сохраняются (R7). Противоречие с условием 2
снимается не удалением ссылок, а **манифестом**. Надгробие
`research/reputation-technologies/README.md` остаётся по пути и перечисляет
каждый бывший путь с адресом замены: SHA-ссылка на спицу, ссылка на тег архива
или отметка «удалён; последняя версия — `<SHA>`». Это compatibility redirect для
префикса, а не для файла. Его вводит ADR-022 и описывает
`artifact-deprecation-standard` v0.3.

«Книга эволюции», о которой пишет владелец, уже существует — это
[`docs/history.md` спицы](https://github.com/G-Ivan-A/aether-orbis-gra/blob/1669943e6f0193e78b245bb9d26b3281a1c5a438/docs/history.md)
(97 строк, `status: reviewed`, «Задачи, PR и устаревшие рабочие материалы Хаба
сюда не переносились; при необходимости на них даются ссылки»). Хабу не нужна
вторая книга. Нужен адрес, на который её ссылки смогут указывать после
очистки, — SHA или тег.

### F-6. Каталог-архив против тега: что показывает проба

| `blob/34defa5…/pr-ops/README.md` (родитель коммита удаления) | 200 |

Следовательно, `path_migrations` — правило валидатора
(`resolve_declared_path_migration` принимает битую ссылку, только если файл по
новому пути существует локально), а не веб-перенаправление. GitHub тоже
отвечает, что для устойчивой ссылки нужен permalink на коммит
([документация](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files)).

| Критерий | A. Каталог `archive/` в дереве (пожелание issue) | B. Аннотированный тег + удаление из дерева + манифест |
| --- | --- | --- |
| Ссылки `blob/main/research/reputation-technologies/...` | 404: путь меняется | 404: путь исчезает |
| SHA-ссылки | Работают | Работают |
| Относительные ссылки внутри архивного снимка | Ломаются при перемещении, если не переписывать | Работают внутри тега: снимок не тронут |
| Объём в контексте агента и полнотекстовых проверках | Остаётся 8,66 МБ (33,5 % байтов Хаба) | Уходит из дерева |
| Пропуск валидаторами | Одно правило `archive/*` в каждом валидаторе и в `validate.yml` | Не нужен: файлов нет |
| Защита от правки | Нужен отдельный запрет (CODEOWNERS или проверка неизменности) | Тег защищается ruleset ([правила защиты тегов заменены rulesets](https://github.blog/changelog/2024-05-29-sunset-notice-tag-protections)) |
| Обнаружимость для человека | Высокая: каталог виден в дереве | Через манифест в надгробии и список тегов |

Каталог-архив не сохраняет ни одной ссылки `blob/main`, которую не сохраняет
тег, и при этом оставляет 33,5 % байтов в каждом поиске агента. Anthropic
описывает это как «context rot» и рекомендует давать модели «smallest possible
set of high-signal tokens»
([источник](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)).
Исключение каталога для агента через `permissions.deny` в настройках агента
лишь частичное: `grep -r` из оболочки его обходит (внешний отчёт, слабое
доказательство). **Вывод: B — основной вариант, A — запасной**, и только с
обязательными мерами: правило пропуска, запрет правок и исключение для агентов.
Это первое предупреждение об индустриальной практике (IPA-1) в RFC.

### F-7. Персональные данные

`2026-10-14-day1-lecturer-gra-research.md` — исследование открытых данных о
конкретном человеке. На него ведут 10 плавающих ссылок спицы (колода дня 2).
Архив по определению хранит содержимое. Тег или каталог продолжили бы
тиражировать персональные данные, поэтому такой файл не архивируется, а
удаляется из дерева. Полное удаление из истории git (переписывание истории)
меняет все SHA и ломает каждую закреплённую ссылку, включая 51 ссылку спицы.
Это решение только владельца (Q-3 в RFC, IPA-3). Без него в этом PR действует
меньшее: файл не попадает ни в один архив и в манифесте помечен «удалён».
