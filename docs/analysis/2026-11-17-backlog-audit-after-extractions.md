# Аудит бэклога Хаба после выносов (PR #739, #743)

## Summary / BLUF

Бэклог на `main@24cd7ff` отставал от фактов в двух местах. Первое — вынос
метамодели БА: этапы E1–E6 слиты в `ba-ai-metamodel` (PR #2–#7, `e1f67e2`),
а B-244…B-247 стояли в `TODO`. Второе — вынос `aether-orbis-proxeneta`:
владелец принял импорт и подтвердил PRIVATE, а B-309 и B-310 стояли в
`ЧАСТИЧНО`. Статусы исправлены по проверяемым источникам.

Отдельно найдены три строки, которые противоречат правилу RFC #715 о
принадлежности BA-строк спице (B-264…B-266). Они не отменены: для `CANCELLED`
нужно решение владельца. Решение вынесено в вопросы PR.

Критический блокер один: защиту тегов `archive/*` (Q-6, B-281) нельзя включить
на приватном Хабе текущего тарифа. GitHub отвечает HTTP 403 «Upgrade to GitHub
Pro or make this repository public», поэтому инструкция в `archive-tag`
невыполнима. Workflow теперь говорит об этом прямо; решение — за владельцем.

Задачи финальной очистки Хаба существуют. Для метамодели БА это B-249 с
надгробием, ссылками и снятием заморозки, B-250 — замер; обе исполняются в
PR #745. Для proxeneta очистка выполнена в PR #743. Для GRA остаётся только
ruleset B-281. Новых задач аудит не создаёт.

## Постановка задачи

Источник — [issue #744](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/issues/744).

1. Для каждого активного спринта Хаба ответить, почему он остаётся в Хабе, а
   не в спице.
2. Перечислить задачи, которые противоречат фактам выноса, и исправить статусы
   там, где есть проверяемый источник.
3. Проверить, что задачи очистки Хаба (надгробия, ссылки, снятие заморозки CI)
   существуют и упорядочены.

Граничные случаи и принятые правила:

- **Параллельный PR.** [PR #745](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/pull/745)
  (надгробие B-249) открыт и меняет BA-разделы, B-248…B-250 и строку
  экосистемы. Этот аудит их не трогает. Строки B-244…B-247 записаны тем же
  текстом, что в #745, чтобы слияние двух PR не давало конфликта по ним.
  Исключение одно: B-246 не утверждает, что шаги CI уже сняты, — на `main` они
  ещё есть.
- **Коррекция после слияния.** Сессия #742 после слияния PR #743 записала
  коммит [`378db9b`](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/commit/378db9b1b07a320bce8811e600a9bd7c56370e06)
  в уже слитую ветку, и в `main` он не попал. Аудит переносит его через
  `cherry-pick -x`, без переписывания.
- **`CANCELLED` без решения не ставится.** По
  [инструкции бэклога](../../ops/backlog-instruction.md) отмена требует явного
  решения человека в issue, PR или ADR. Правило RFC #715 разрешает отмену, но
  само её не выполняет. Поэтому противоречащие строки помечены, а отмена
  предложена владельцу.
- **Приоритеты.** У B-249, B-250 и других шагов RFC #715 приоритет `null`, и
  источника для P-уровня нет. Порядок задают зависимости. Назначение
  приоритетов — шаг Ш6.4 (B-261). Аудит его не подменяет.
- **Задача #744 в бэклог не добавляется**: она исполняется этим PR.
