# Готовность к Спринту 31: контрольная проверка перед очисткой Хаба от GRA

## Summary / BLUF

**Спринт 31 готов к исполнению, кроме одного действия администратора.** Блокер
issue #725 снят: PR #4 спицы `aether-orbis-gra` слит 2026-11-04. В спице не
осталось ни одной плавающей ссылки на домен Хаба. Все 78 закреплённых путей
существуют на своих коммитах. Домен не менялся после `PIN_SHA` (`48ebe52`).
Ответы владельца в issue #725 закрывают Q-1…Q-6 и предупреждения IPA-1…IPA-3.

Не готово одно: Q-6. Ruleset на теги `archive/*` включает только администратор
репозитория, а у исполнителя есть право `push`, но не `admin`. Задача B-281
выполняется частично: тег ставит workflow после merge, а ruleset — человек.
Пока ruleset не включён, CI на `main` падает с инструкцией, что сделать.

Повторный прогон инвентаря нашёл новое: ещё **11 единиц (34 файла)** теперь
подходят под удаление R9. Мандат Q-2 их не покрывает, поэтому они уходят в тег,
а не в удаление.

## Context / Scope

Issue #725 — отдельная постановка очистки Хаба (B-286, суб-issue S-2 и S-3
RFC #721). Владелец ответил на шесть вопросов RFC и поставил задачу: провести
контрольную проверку готовности, затем выполнить Спринт 31.

В рамках: предусловия шагов 3–6 RFC #721 и задачи B-268…B-286. Вне рамок: задачи
спицы (GRA-003, GRA-004), которые исполняются в `aether-orbis-gra`.

Проверка — только чтение. Клон спицы — недоверенные данные: `python3 -I`, код
спицы не исполняется. Воспроизведение:

```bash
research/hub/exp/gra-extraction-cleanup-721/sprint31-readiness.sh . /tmp/spoke-ro/aether-orbis-gra
```

### Находки

**F-1. Q-6 требует администратора.** API `repos/.../rulesets` отвечает, но
создать ruleset может только роль `admin`. Это не обходится через workflow:
`GITHUB_TOKEN` не получает права администрирования. Варианты:

- (a) ждать администратора и не ставить тег — тогда шаг 5 останавливается;
- (b) поставить тег workflow после merge и проверять ruleset в CI `main`,
  чтобы его отсутствие было видно, — **выбрано**. Тег без ruleset можно
  удалить, но коммит архива всё равно достижим из `main`, так что потери
  содержимого нет.

**F-2. Сдвиг диспозиций после закрепления ссылок спицы.** Одиннадцать единиц
перешли из ARCHIVE в DELETE (34 файла): `exp/day1-osint-709/`,
`exp/day1-rebuild-677/`, `exp/day3-gamma-681/`, `exp/day4-v5-697/`,
`exp/rfc-days-logic-667/` и шесть файлов (`day1-presentation-653`,
`day1-rebuild-task-671`, `day2-presentation`, `day3-presentation`,
`day4-lecturer-script-v3`, `day4-presentation-gamma-v4`). Причина: правило R8
держало их в архиве из-за плавающих ссылок спицы, а PR #4 закрепил эти ссылки
на SHA.

Документ цитат перешёл из REIMPORT в TOMBSTONE: спица его доимпортировала.

Мандат Q-2 — конкретный список из 19 единиц, а не правило. Поэтому эти 11 единиц
идут в тег (правило неопределённости стандарта). Удалять их отдельно смысла нет:
тег их и так не тиражирует в рабочее дерево.

**F-3. Порядок стандарта и один PR.** Стандарт выбытия требует, чтобы шаги 3 и
5 были отдельными PR, а тег стоял на merge-коммите шага 3. Issue #725 требует
выполнить спринт в этом PR. Варианты:

- (a) два PR — тогда шаг 5 ждёт merge первого PR, и issue не закрывается одним
  PR;
- (b) один PR, но шаги 3 и 5 — отдельные коммиты. Тег ставится на коммит шага 3,
  объявленный в `.hub-profile.json` (`archive_commit`). Workflow после merge
  проверяет, что коммит содержит весь архив и не содержит удалённого по мандату,
  и только тогда ставит тег — **выбрано**.

Цена варианта (b): между merge и прогоном workflow тега ещё нет. Условие — merge
обычным merge-коммитом, без squash и rebase. Иначе коммит шага 3 не попадёт в
историю `main`, и workflow сообщит об этом. Содержимое всё равно не пропадёт:
тег держит коммит, а GitHub хранит `refs/pull/726/head`.

**F-4. #650 и Q-3.** Ответ «переносим в спицу» исполняется в спице, задача
GRA-003. В Хабе #650 уходит в тег, а строка манифеста указывает адрес на теге.
Когда спица перенесёт документ, строку манифеста можно перевести на SHA спицы:
надгробие — обслуживаемый указатель, а не историческая запись.

**F-5. #292 и Q-3.** Чтобы оставить стратегию партнёров в Хабе после удаления
домена, её нужно вынести из каталога домена. Выбран `research/education/`:
это исследование о привлечении партнёров для образовательных программ, а
`research/education/` уже есть в индексе research. Перенос фиксируется
файловой записью `path_migrations` и строкой манифеста.

## Recommendations

1. **Исполнять Спринт 31 в этом PR**, в порядке стандарта: сигнал и манифест →
   перепись живых ссылок → удаление R9 и PII (коммит архива) → вынос остального
   → реестры. *Обоснование:* все предусловия, кроме Q-6, выполнены (P-1…P-7).
2. **Администратору — включить ruleset `archive/*`** (B-281). Готовая команда и
   JSON — в описании PR #726. *Обоснование:* без этого тег можно удалить или
   передвинуть, и CI `main` будет красным с явной инструкцией.
3. **Сливать PR #726 обычным merge-коммитом.** *Обоснование:* F-3 — тег
   ставится на коммит архива внутри PR.
4. **Не расширять мандат Q-2 на 11 единиц из F-2.** *Обоснование:* тег не
   нагружает рабочее дерево, а удаление требует нового мандата без выигрыша.
5. **В спице:** исполнить GRA-003 (Q-3 «перенести») и закрыть GRA-004 (Q-4 — история не переписывается, закреплённые ссылки работают).
   *Обоснование:* оба триггера наступили с ответом владельца.
