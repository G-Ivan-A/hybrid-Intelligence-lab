# Дефекты генома B и D (B-240)

## Summary / BLUF

Геном после B-239 переносил в спицы ссылки на изменяемую ветку Хаба, помещал
полные HTOM-контракты в корень и оставлял `ops/` без общих операционных
документов. B-240 связывает ссылки с коммитом синхронизации и определяет места
для правил и операций. Для существующих E1-спиц переход также требует сравнения
с исторической картой и сохранения настроенного проектом CI.

## Context / Scope

Разбор от 28 ноября 2026 года подготовлен Codex по задаче G-Ivan-A. Точка
отсчёта — декларация генома и синк из [PR #755][b239]. Подтверждены R-2 и R-3
из F-2 [анализа #738][f2]. Затронуты чистые спицы B и D и переход
`ba-ai-metamodel`, созданной этапом E1. Задача пользователя — создавать и
обновлять спицу с воспроизводимыми правилами Хаба, сохраняя её проектные файлы.

## Findings / Options

До B-240 архетип B брал `templates/spoke/`, общие шаблоны issue и валидатор
загрузки `AGENTS.md`. Архетип D брал дерево `templates/htom/` без скрипта
инициализации, профиля и README. В обоих архетипах инструмент создавал профиль
отдельно. Отсутствие `ops/` в поставке B и D согласуется с H-1 из R-2.

| Путь на исходной ревизии | Дефект и доказательство | Исправление |
| --- | --- | --- |
| `templates/spoke/AGENTS.md` | R-3, I-3. На 10 строках 12 ссылок `blob/main`, ещё одна ведёт на `tree/main/standards`. | Подставить разрешённый SHA во все 13 ссылок. |
| `templates/spoke/README.md` | R-3, I-3. Одна плавающая ссылка в шаблоне, который был исключён из карты B. | Закрепить ссылку и доставлять README при наличии свободного пути. |
| `templates/htom/AGENTS.md`, `templates/htom/README.md` | Та же зависимость от `main` на втором архетипе. В README четыре ссылки `blob/main`. | Применить ту же подстановку SHA. README доставляется как стартовый файл. |
| `templates/htom/AI_QUICK_RULES.md`, `AI_SESSION_HANDOVER_PROMPT.md`, `AI_GOVERNANCE.md` | H-3 (R-2). Три полных документа в корне конкурировали с единой точкой входа. Прежний Smart Sync также предлагал handover для B. | Полные правила и handover в `ai-rules/`, политика в `ai-governance/`. Три прежних корневых пути D содержат генерируемые указатели с локальным маршрутом и SHA источника. |
| `tools/hub-genome.json`, `templates/htom/tools/validate-repository-structure.sh` | H-1 (R-2). Геном не поставлял общие операции, хотя контракты отводили им `ops/`. Состав D также не согласовывался с обязательным README в валидаторе. | Поставлять `ops/backlog-instruction.md` и `ops/artifact-map.md` в B и D. В D проверить состав генома и точный формат корневых указателей. |
| `tools/hub-sync.py`, `templates/spoke/.github/workflows/ci.yml` | На `ba-ai-metamodel@e1f67e267beb` план из B-239 остановился на единственном конфликте — проектном CI. Профиль спицы закреплён на `54face1618f74154ae0f072bc3e5bfb3c4817754`, до появления декларации. | Сравнивать известные старые E1 с исторической картой. Сделать README и CI B стартовыми, сохраняя пользовательскую версию. |

Подстановка по тегу как по строке сохраняла бы зависимость от изменяемой
ссылки. Синк сначала разрешает тег в коммит, а затем использует один SHA для
ссылок и для `last_sync.hub_sha`. Это согласуется с описанием постоянных
ссылок GitHub. [Getting permanent links to files][permalinks]

Полное исключение README и CI из карты защищало бы существующие спицы, но
оставляло бы чистую спицу без этих файлов. Безусловная установка из Хаба
воспроизводит конфликт `ba-ai-metamodel`. Декларация стартовых файлов
сохраняет оба сценария. Бэклог и журналы спицы ведёт сам проект, поскольку
перенос их владения в Хаб означал бы синхронизацию проектных данных.

## Recommendations

Принять B-240 после проверки двух архетипов и исторического E1. После слияния
запустить B-307 — процедура рождения использует исправленный геном, а её
предпосылки B-236 и B-238 уже в статусе DONE. B-239 (DONE) поставил механизм
закрепления, B-240 закрывает дефекты содержимого, B-307 остаётся TODO до
реализации процедуры и проверки по реестру. [Бэклог](../../ops/backlog.md)

## Проверка

| Сценарий | Воспроизводимая проверка |
| --- | --- |
| Чистый B, закрепление SHA и тега | `tools/test-hub-sync.py`, `test_no_floating_links_after_sync`. Ссылки проверяются по объектам Git, в том числе после смены закрепления при неизменном исходном шаблоне. |
| Чистый B и проектные изменения | `test_archetype_b_installs_ops_and_preserves_project_starters`. Проверяются `ops/`, `ai-rules/`, `ai-governance/`, синк поверх изменённых README и CI, а также отсутствие повторной записи профиля. |
| D и корневые указатели | Тест D запускает валидатор сгенерированной спицы и проверяет обнаружение подмены указателя как валидатором структуры, так и каноническим `verify`. |
| Переход с E1 | Интеграционный тест материализует E1 через `spoke-extraction.py`, сравнивает его с результатом `hub-sync` на том же SHA и проверяет, что синк изменяет только профиль. |
| Существующая спица B | В чистом локальном клоне `ba-ai-metamodel@e1f67e267beb` применить `plan`, `sync`, затем `verify`. Сравнить проектные README, CI и бэклог с исходным Git, проверить профиль и повторить синк на том же SHA. |
