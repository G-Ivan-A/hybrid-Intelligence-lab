## Context

Версия 0.1 мета-модели объявила четыре канонические таксономии, но словари
процессов и операций в ней были **унаследованы из спицы без проверки**. Замер
на коммите корпуса `8cbf82a` и коммите Хаба `15aa76f`
([отчёт](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/research/ba-requirements/2026-09-10-process-taxonomy-defects-facts.md))
показал восемь дефектов.

| Дефект | Что измерено |
| --- | --- |
| `D1` | 29 мест корпуса склеивают ФТ и ТЗ в одно имя выхода («ФТ/ТЗ»), хотя это два артефакта с разными контрактами и разными адресатами |
| `D2` | 4 места объявляют границей процесса состояние документа («черновик»), а не смену класса артефакта |
| `D3` | 7 операций из 13 производят более одного класса выхода |
| `D4` | 8 операций из 13 перечисляют разнородные результаты внутри одного определения |
| `D5` | уровень подпроцесса существует в исполнении (6 именованных подпроцессов `П1`–`П6`) и отсутствует в мета-модели |
| `D6` | сущности `Система`, `Пользователь`, `Подпроцесс` в мета-модели отсутствуют при 5 промптах, требующих акторов |
| `D7` | 66 меток `process` из 67 прогонов лежат вне объявленного словаря |
| `D8` | маршрут описан линейным списком шагов: 1 маркер ветвления, 2 утверждения неизменности |

Ключевой пример `D1` и `D2` — процесс `fr-generation`, определённый как «от
сырого запроса до черновика ФТ/ТЗ». Определение соединяет два разных целевых
артефакта и объявляет границей процесса состояние документа. Оно попало в
мета-модель переносом из истории, а не выводом, то есть является прямым
нарушением `LG-5`.

## Decision

**Таксономии процессов и операций пересобираются заново: `L0` и `L1`
наследуются из BABOK Guide v3, `L2` и `L3` выводятся как обоснованная дельта
предметной области КК Манго, а унаследованные из спицы словари девяти процессов
и тринадцати операций переводятся в `deprecated` с пообъектным реестром
замены.**

| Правило | Формулировка |
| --- | --- |
| `TX-1` | Верхние уровни таксономии процессов (`L0` области знаний, `L1` семейства работ) наследуются из индустриального стандарта (BABOK Guide v3) и не изобретаются. |
| `TX-2` | Уровни `L2` (процессы) и `L3` (навыки-подпроцессы) объявляются дельтой предметной области: у каждого элемента указано, чем он отличается от базиса — предметом, формой или гранулярностью. |
| `TX-3` | Границей процесса является смена класса артефакта, а не состояние документа. Состояние (`draft`, `validated`, `approved`) — атрибут артефакта. |
| `TX-4` | Один процесс имеет ровно один целевой класс выхода. Имя выхода вида «ФТ/ТЗ» запрещено. |
| `TX-5` | Операция атомарна: один класс выхода, отсутствие ветвления, один тип когнитивной работы. Всё, что требует последовательности или ветвления, является навыком-подпроцессом. |
| `TX-6` | Элемент прежнего словаря переносится в новый только с пообъектной проверкой и записью в реестре депрекации: имя, причина, замена. |
| `TX-7` | Таксономия проверяется машинно: словари извлекаются из текста модулей, а покрытие проверяется на синтетических кейсах. |

**Что сделано по этому решению.**

1. Аудит исторического корпуса и датированный отчёт о восьми дефектах.
2. Модуль [`ba-process-taxonomy/`](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/tree/main/projects/ba-gigacode-implementation/ba-process-taxonomy):
   `L0` — шесть областей знаний BABOK, `L1` — пять семейств работ, `L2` — десять
   процессов `P-01`…`P-10`, `L3` — 33 навыка с ярусами контроля `G1`–`G7`.
3. Модуль [`ba-operation-taxonomy/`](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/tree/main/projects/ba-gigacode-implementation/ba-operation-taxonomy):
   31 операция в пяти классах (`extract`, `transform`, `generate`, `check`,
   `assess`), шестиполевой контракт операции, разложение всех 33 навыков.
4. Реестры депрекации девяти процессов и тринадцати операций с указанием замены
   для каждого.
5. Семь синтетических кейсов и машинный валидатор покрытия.

## Decision Drivers

| Драйвер | Содержание |
| --- | --- |
| Измеримость дефекта | Решение опирается на восемь замеренных дефектов, а не на впечатление о качестве словаря. |
| Индустриальный базис | BABOK Guide v3 даёт проверенную временем структуру верхних уровней и снимает вопрос «почему именно эти семейства работ». |
| Исполнимость агентом | Каждый навык получил ярус контроля `G1`–`G7`, каждая операция — условие отказа: без этого процесс описан для человека, а не для агента. |
| Разделение артефактов | ФТ, ТЗ, `BCREQ`, `A-CORE` и `A-TRACE` получили несовпадающие контракты, поэтому склейка имён выхода стала обнаружимой. |
| Проверяемость | Словари извлекаются валидатором из текста модулей: расхождение текста и проверки невозможно по построению. |

## Alternatives Considered

| Альтернатива | Почему отклонена |
| --- | --- |
| **Отредактировать девять унаследованных процессов, не пересобирая таксономию** | Дефекты `D1`–`D4` структурные: они лежат в самом принципе нарезки (по стадии работы, а не по смене класса артефакта). Правка формулировок сохранила бы принцип и вернула бы те же дефекты при следующем расширении. |
| **Взять базисом не BABOK, а IREB CPRE или SWEBOK** | IREB покрывает только требования и не покрывает `L1-ASSESS` и `L1-MANAGE`, нужные КК Манго; SWEBOK описывает инженерию ПО целиком, и БА в нём — одна глава. Сопоставление с обоими вынесено в задачу `B-158`. |
| **Оставить `Skill` реализацией операции** | Противоречит замеру `D5`: уровень подпроцесса наблюдается в исполнении. Без него не выражается ветвление внутри участка работы и точка гейта. |
| **Не депрекировать старые словари, а вести два параллельно** | Прямое нарушение `K-3` (единственность имени) и источник расхождения при компиляции пакета. |
| **Отложить до появления реальных прогонов по новому словарю** | Замер `D7` показывает, что прогонов по старому словарю практически нет (1 из 67); ждать эмпирики словаря, которым не пользуются, — ждать бесконечно. Проверка выполнена синтетическими кейсами. |

## Consequences

**Положительные.**

- Процессы и операции стали выразимы: 33 шага семи синтетических кейсов
  выражаются новым словарём полностью и не выражаются прежним ни одним шагом.
- Каждый элемент таксономии проверяется машинно, включая полноту разложения
  навыков на операции и покрытие кейсами.
- Артефакты `A-CORE`, `A-TZ`, `A-BCREQ`, `A-REP`, `A-TRACE` получили контракты,
  различающие их по адресату и по содержанию, а не по названию.

**Отрицательные и риски.**

- Все ссылки на прежние имена процессов и операций в модулях `M0`–`M4` и в
  осевых модулях становятся устаревшими; сквозной рефакторинг вынесен в бэклог,
  а не выполнен правкой исторических текстов.
- Новый словарь не проверен ни одним реальным прогоном: доказана выразимость,
  а не пригодность на практике.
- 33 навыка — существенно больше прежних 13 операций; риск избыточной
  дробности снимается только эмпирикой (`B-157`).

## Compliance and Validation

| Проверка | Форма | Кто выполняет |
| --- | --- | --- |
| Навык принадлежит объявленному процессу и имеет ярус контроля | машинная: `validate-new-taxonomy.py`, проверка `C1` | исполнитель, CI |
| Словари навыков в обоих модулях совпадают | машинная, `C2` | исполнитель, CI |
| Разложение навыка использует только операции каталога | машинная, `C3` | исполнитель, CI |
| Контракт операции заполнен по всем шести полям | машинная, `C4` | исполнитель, CI |
| Каждая операция каталога вызывается хотя бы одним навыком | машинная, `C5` | исполнитель, CI |
| Шаги синтетических кейсов выразимы в новом словаре | машинная, `C6`, `C7` | исполнитель, CI |
| Прежний словарь невыразителен для тех же шагов | машинная: режим `--legacy` | исполнитель |
